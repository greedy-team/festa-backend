### 📌 작업 개요

프론트(`festa-frontend`)에서 확정한 자동화 설정을 백엔드에 맞췄다.
커밋 메시지 형식이 두 레포에서 서로 달랐고, PR 머지 시 이슈 자동 종료가 백엔드에만 없어
매번 수동으로 닫아야 하던 상태를 정리했다.

### 🔍 문제 분석

**커밋 형식이 갈려 있었다.**

| 레포 | 봇이 제안하던 형식 |
| --- | --- |
| 백엔드 | `로그인 오류 : fix : {설명} <이슈 URL>` |
| 프론트 | `fix : {설명} #5` |

같은 팀이 두 레포를 오가는데 규칙이 다르면 어느 쪽도 지켜지지 않는다.
더 실질적인 문제는 이슈 참조 형태였다 — URL로 적으면 GitHub가 이슈 타임라인에 커밋을 연결하지 않는다.

**형식을 고치려 하자 설정 파서가 막았다.** `version.yml`을 읽는 `load_config`가 값에서
`\s+#.*$`를 주석으로 잘라내는데, 이 정규식은 따옴표 안팎을 구분하지 않는다.
커밋 템플릿에 이슈 번호를 `#${issueNumber}` 형태로 넣는 순간 그 뒤가 통째로 잘린다.

**이슈 자동 종료가 없었다.** 백엔드에는 머지 시 이슈를 닫는 워크플로우 자체가 없었다.

### ✅ 구현 내용

#### 설정 파서의 인라인 주석 처리 수정

- **파일**: `.github/scripts/issue_helper.py`
- **변경 내용**: `_strip_inline_comment()` 추가. 값이 따옴표로 시작하면 닫는 따옴표까지를 값으로 보고,
  따옴표가 없을 때만 기존처럼 ` #...`을 주석으로 제거한다
- **이유**: 이 함수가 없으면 커밋 템플릿에 `#번호`를 넣을 수 없다. 형식 통일의 선행 조건이다

#### 커밋 템플릿을 프론트와 통일

- **파일**: `version.yml`
- **변경 내용**: `issue_helper.commit_template`에 `"${commitType} : {변경 사항에 대한 설명} #${issueNumber}"` 지정
- **이유**: 설정은 코드 기본값이 아니라 `version.yml`에 둔다. `.github/scripts/`는 `npx projectops`
  업데이트 때 덮어써지는 영역이다

#### 이슈 자동 종료 워크플로우 추가

- **파일**: `.github/workflows/PROJECT-COMMON-CLOSE-ISSUE-ON-MERGE.yaml` (신규, 88줄)
- **변경 내용**: `develop`으로 향한 PR이 머지되면 브랜치명에서 이슈 번호를 뽑아 라벨을 `작업완료`로
  교체하고 이슈를 닫는다. 종료 코멘트로 PR 번호와 링크를 남긴다
- **이유**: 수동 종료를 없애고, 이슈 상태가 실제 머지 상태를 따라가게 한다

#### 작업 산출물 폴더 무시

- **파일**: `.gitignore`
- **변경 내용**: `docs/superpowers/`(스펙·계획 문서), `.superpowers/`(워크스페이스) 추가
- **이유**: 릴리스 워크플로우가 `git add -A`로 커밋하기 때문에, 워킹 트리에 남은 임시 산출물이
  릴리스 커밋에 쓸려 들어간다

### 🧭 결정 기록 (ADR)

#### 이슈 번호를 `Closes #N`이 아니라 브랜치명에서 뽑음

- **문제**: 머지된 PR이 어느 이슈를 닫아야 하는지 알아내는 방법
- **선택**: 브랜치명 `타입_이슈번호_슬러그`에서 정규식으로 추출
- **대안**:
  - PR 본문의 `Closes #N` — 이 흐름에서는 동작하지 않는다. closing keyword는 기본 브랜치(`main`) 머지에서만
    동작하는데 작업 PR은 `develop`으로 머지되고, 릴리스 PR 본문은 RELEASE-CHANGELOG가 CHANGELOG로 덮어쓴다
  - PR 제목 파싱 — 사람이 자유롭게 고쳐 쓰는 값이다
- **트레이드오프**: 브랜치명 규칙을 어기면 이슈가 닫히지 않는다. 브랜치명은 봇이 제안하는 값이라
  사람이 덮어쓸 일이 적다는 점에 기댔다
- ⭐ **볼트 승격 권장** — 두 레포에 공통으로 적용되는 자동화 규약이다

#### 브랜치명이 규칙에 안 맞으면 통과시킴

- **문제**: 이슈 번호를 못 뽑았을 때 워크플로우를 실패시킬지
- **선택**: 로그만 남기고 `exit 0`. 이슈를 못 찾거나 이미 닫혀 있어도 마찬가지다
- **대안**: 실패 처리 — 규칙 위반을 즉시 드러낼 수 있다
- **트레이드오프**: 이슈가 조용히 안 닫히는 경우가 생긴다. 그래도 **이슈 종료 실패가 머지를 막을 이유는 없다**는
  쪽을 택했다. 라벨 교체도 같은 이유로 실패해도 종료를 막지 않게 했다

### 🧪 테스트 및 검증

- 파서 수정은 `#${issueNumber}`가 포함된 템플릿이 잘리지 않고 그대로 렌더링되는지로 확인
- 이슈 종료 워크플로우는 이후 실제 머지에서 동작을 확인했다. 현재 저장소의 닫힌 이슈에는
  `PR #N 머지로 완료되었습니다` 코멘트가 남아 있다

### 📌 참고사항

- 이 작업은 설정·워크플로우 파일만 건드린다. 빌드·배포·런타임에는 영향이 없다
- 브랜치 전략 안내 문구도 함께 갱신했다. 다만 문구는 `main` → Vercel Production,
  `develop` → Vercel Preview로 되어 있어 프론트 기준 표현이 백엔드 봇 댓글에도 그대로 나온다.
  백엔드 배포는 이후 별도 이슈에서 OCI로 구성했으므로, 봇 댓글의 이 문구는 현재 백엔드 실제 배포와 다르다
