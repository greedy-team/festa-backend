### 📌 작업 개요

Issue #27의 관리자 로그인 API와 관리자 전용 JWT 인증을 구현했다. `AdminUser`의 아이디·비밀번호를
검증해 액세스 토큰을 발급하고, `POST /admin/auth/login`을 제외한 `/admin/**` 요청에 인증을 적용한다.

이 문서는 PR #29 최신 head `5b538be`를 기준으로 작성했다.

**보고서 파일**: `docs/reports/20260820_27_관리자_로그인_API와_JWT_인증_추가.md`

### 🎯 구현 목표

- `POST /admin/auth/login` 관리자 로그인 API 제공
- `AdminUser.username`과 BCrypt 비밀번호 해시를 이용한 자격 증명 확인
- 일반 사용자 JWT와 분리된 관리자 JWT 발급·검증
- 로그인 API만 공개하고 나머지 `/admin/**` 요청은 인증 필요
- 세션을 만들지 않는 stateless Bearer 인증 구성
- 만료 토큰과 그 밖의 유효하지 않은 토큰을 서로 다른 401 코드로 반환
- 환경변수를 이용한 초기 관리자 계정 생성

### ✅ 구현 내용

#### 관리자 로그인 API

- **파일**: `AdminAuthController.java`, `AdminLoginRequest.java`, `AdminLoginResponse.java`,
  `AdminAuthService.java`
- **엔드포인트**: `POST /admin/auth/login`
- **요청**: `username`, `password`
- **성공 응답**: `accessToken`, `expiresIn`
- **인증 처리**: username으로 `AdminUser`를 조회한 뒤
  `PasswordEncoder.matches(rawPassword, passwordHash)`로 비밀번호를 검증한다. 검증이 끝난 뒤에만
  관리자 JWT를 발급한다.
- **실패 처리**: username이 없거나 비밀번호가 일치하지 않는 경우 모두
  `ADMIN_INVALID_CREDENTIALS`를 사용한다. 외부 응답은 HTTP 401과 동일한 4필드
  `ErrorResponse(errorCode, message, status, instance)`이며 계정 존재 여부를 구분하지 않는다.

이 정책은 관리자 로그인 계약을 정한 DEC-0085와 일치한다. 존재하지 않는 username 경로와 비밀번호
불일치 경로의 내부 처리 시간 차이를 맞추는 더미 BCrypt 비교는 구현하지 않았다.

#### 관리자 JWT 발급과 검증

- **파일**: `JwtTokenProvider.java`, `ClockConfig.java`
- **클레임**: subject에 관리자 username을 넣고 issued-at과 expiration을 설정한다.
- **서명 키**: `app.jwt.admin-secret`을 Base64 decode해 HMAC 키로 사용한다.
- **설정**: `ADMIN_JWT_SECRET`이 `app.jwt.admin-secret`에 바인딩된다. 일반 JWT 설정인
  `app.jwt.secret`/`JWT_SECRET`과 별도 프로퍼티 및 키 객체를 사용한다.
- **만료 시간**: `app.jwt.admin-token-validity=PT1H`, 즉 1시간이다. 로그인 응답의
  `expiresIn`은 3600초다.
- **Clock**: 운영 Bean은 `Clock.systemUTC()`이며 테스트에서는 고정 Clock으로 교체해 발급·만료를 검증한다.

서명 키가 다르면 일반 JWT를 관리자 JWT parser가 검증하지 못한다. 코드에서는 관리자용과 일반용
프로퍼티를 분리하지만, 배포 설정에서 두 Secret에 같은 실제 값을 넣는 것까지 비교해 차단하지는 않는다.

#### SecurityConfig와 stateless 인증

- CSRF, form login, HTTP Basic을 비활성화한다.
- `SessionCreationPolicy.STATELESS`를 적용해 HTTP 세션에 인증을 저장하지 않는다.
- `POST /admin/auth/login`만 `permitAll`로 선언한다.
- 그 뒤의 `/admin/**` matcher에는 `authenticated()`를 적용한다.
- 그 밖의 요청은 기존 공개 API 동작을 유지하도록 `permitAll`이다.
- `JwtAuthenticationFilter`를 `UsernamePasswordAuthenticationFilter` 앞에 배치한다.
- 역할을 나누거나 `ROLE_ADMIN` 권한을 만들지 않고 인증 여부만 확인한다(DEC-0083).

PR #29가 직접 보호하는 matcher는 `/admin/**`이다. `/api` 접두사 제거는 별도 PR #28의 변경이며
이 리포트의 구현 내용에 포함하지 않는다.

#### JwtAuthenticationFilter 동작

- Authorization 헤더가 없거나 `Bearer ` 형식이 아니면 인증을 만들지 않고 다음 필터로 진행한다.
- 유효한 관리자 JWT이면 subject를 principal로 하는 인증 객체를 `SecurityContext`에 설정한다.
- 만료 토큰이면 request attribute에 `TOKEN_EXPIRED`를 기록한다.
- malformed JWT, 빈 Bearer 값, 잘못된 서명 등 그 밖의 invalid token이면 `UNAUTHORIZED`를 기록한다.
- 필터는 JWT 예외를 응답으로 직접 쓰지 않고 다음 필터로 진행한다. 보호된 `/admin/**`에서 인증이
  없으면 `JwtAuthenticationEntryPoint`가 최종 401 응답을 만든다.
- 공개된 로그인 API에 잘못된 Authorization 헤더가 함께 들어와도 matcher가 `permitAll`이므로 로그인
  요청 자체는 차단하지 않는다.

#### JwtAuthenticationEntryPoint와 에러 응답

- request attribute에 저장된 ErrorCode가 있으면 해당 코드를 사용한다.
- attribute가 없으면 `UNAUTHORIZED`를 기본값으로 사용한다.
- 만료 JWT는 HTTP 401 `TOKEN_EXPIRED`, 그 밖의 유효하지 않은 JWT와 토큰 누락은 HTTP 401
  `UNAUTHORIZED`로 응답한다.
- 응답은 프로젝트 공통 계약인 `errorCode`, `message`, `status`, `instance` 네 필드다(DEC-0041).

#### AdminAccountSeeder

- **파일**: `AdminAccountSeeder.java`, `application.yml`
- **환경변수**: `ADMIN_INITIAL_USERNAME`, `ADMIN_INITIAL_PASSWORD`
- 두 값 모두 없거나 공백이면 의도적인 seeding 비활성화로 보고 계정 생성을 건너뛴다.
- 두 값 모두 있으면 같은 username의 존재 여부를 먼저 확인한다.
- 같은 username이 이미 있으면 중복 생성하거나 기존 비밀번호를 변경하지 않는다.
- 계정이 없으면 비밀번호를 BCrypt encode해 `passwordHash`로 저장한다.
- 둘 중 하나만 설정되면 `IllegalStateException`을 던져 애플리케이션 기동을 fail-fast 한다.
  메시지는 누락된 환경변수 이름과 설정 방법만 포함하며 username/password 실제 값은 포함하지 않는다.

정상 시딩 및 기존 계정 건너뜀 로그에는 username이 포함된다. 비밀번호, 비밀번호 해시, JWT Secret과
토큰은 로그에 출력하지 않는다.

### 🔍 PR #29 리뷰 반영

#### `ffa71af` — 초기 관리자 부분 설정 시 기동 실패

기존 구현은 username/password가 모두 없는 경우와 하나만 설정된 경우를 동일하게 시딩 생략으로
처리했다. 변경 후에는 다음 세 상태를 구분한다.

| 설정 상태 | 동작 |
| --- | --- |
| 둘 다 없음 | 정상 기동, 시딩 생략 |
| 둘 다 있음 | 기존 username 확인 후 필요할 때 BCrypt 계정 생성 |
| 하나만 있음 | `IllegalStateException`으로 fail-fast |

부분 설정 오류에는 민감한 실제 값을 포함하지 않는다. 이 분기를 직접 검증하는
`AdminAccountSeeder` 테스트는 PR head에 추가되지 않았다.

#### `5b538be` — 로그인 실패 401 계약 테스트

`AdminAuthControllerTest`에 로그인 실패 테스트를 추가했다. Service가
`ADMIN_INVALID_CREDENTIALS`를 던질 때 최종 응답이 다음 계약과 일치하는지 MVC 계층에서 검증한다.

- HTTP status 401
- `errorCode=ADMIN_INVALID_CREDENTIALS`
- 개발자용 message
- `status=401`
- `instance=/admin/auth/login`

### 🧭 결정 기록 (ADR)

#### 자체 아이디·비밀번호와 관리자 JWT 사용

- **근거**: DEC-0082
- `AdminUser`의 username/passwordHash를 관리자 자격 증명으로 사용하고 JWT를 발급한다.
- 관리자 토큰은 일반 사용자 토큰과 다른 서명 키를 사용한다.
- Google OAuth는 관리자 로그인 흐름에 사용하지 않는다.

#### 관리자 역할을 나누지 않고 인증만 확인

- **근거**: DEC-0083
- `/admin/**`에서는 `authenticated()`만 요구하며 `ROLE_ADMIN`이나 기능별 권한을 만들지 않는다.

#### 로그인 실패 응답 통합

- **근거**: DEC-0085
- `POST /admin/auth/login`을 신설하고 username 미존재와 비밀번호 불일치를
  `ADMIN_INVALID_CREDENTIALS` 하나로 통합한다.

#### 액세스 토큰 하나와 1시간 만료

- **근거**: DEC-0086
- refresh token은 만들지 않는다.
- 관리자 액세스 토큰 수명은 1시간이다.
- 만료는 `TOKEN_EXPIRED`, 그 밖의 invalid token은 `UNAUTHORIZED`로 구분한다.

### 📦 의존성 및 설정 변경

- Spring Security 및 JJWT의 기존 의존성을 사용한다.
- Controller slice 테스트를 위해 `spring-boot-webmvc-test`를 추가한다.
- `application.yml`에 다음 설정을 추가한다.
  - `app.admin.initial-username=${ADMIN_INITIAL_USERNAME:}`
  - `app.admin.initial-password=${ADMIN_INITIAL_PASSWORD:}`
  - `app.jwt.admin-secret=${ADMIN_JWT_SECRET}`
  - `app.jwt.admin-token-validity=PT1H`

`ADMIN_JWT_SECRET`에는 기본값이 없다. 누락, 잘못된 Base64 또는 HMAC에 부족한 길이의 키는
JwtTokenProvider 생성 과정에서 실패한다.

### 📌 제한사항 및 후속 확인

- `AdminAccountSeeder`의 모두 없음·모두 있음·부분 설정·기존 username 분기를 직접 검증하는 테스트는 없다.
- 로그인 실패 MVC 테스트는 잘못된 비밀번호 요청 하나로 외부 401 계약을 검증한다. username 미존재와
  비밀번호 불일치가 동일 예외가 되는 것은 `AdminAuthServiceTest`에서 각각 검증한다.
- refresh token, 관리자 역할 구분, 관리자 계정 추가·비밀번호 변경 API는 구현 범위에 없다.
- 관리자 JWT에는 role이나 별도 admin claim을 넣지 않는다. 관리자 전용 Secret으로 서명된 토큰의
  유효성과 subject를 인증 근거로 사용한다.
- 관리자 로그인에는 Google OAuth를 사용하지 않지만 기존 OAuth client 의존성·설정 제거는 이 PR에
  포함되지 않았다.
- 실제 배포에서는 `ADMIN_JWT_SECRET`이 `JWT_SECRET`과 다른 값인지, 초기 관리자 seeding을 사용할 경우
  두 `ADMIN_INITIAL_*` 값이 함께 설정됐는지 확인해야 한다.
