- 관련 PR: `#51` — 관리자 아티스트 병합 API 추가

## 구현 범위

- `POST /admin/artists/merge` 추가
- target/source Artist 존재 여부와 요청 값 검증
- source 대표명·별칭의 선택적 이관
- source Lineup의 target 이관과 중복 정리
- 병합 완료 후 source Artist 삭제 및 target 검토 대기 처리
- 단일 트랜잭션과 Artist 비관적 쓰기 잠금 적용

## 주요 구현 내용

### 아티스트 병합

- `targetId`가 없으면 `ARTIST_INVALID_TARGET_ID`, target 또는 source Artist가 존재하지 않으면
  `ARTIST_NOT_FOUND`로 실패한다.
- target이 `sourceIds`에 포함된 자기 자신 병합은 `ARTIST_SELF_MERGE`로 거부한다.
- `sourceIds`의 중복 ID는 제거한 뒤 처리하며, 비어 있거나 null이거나 null 원소가 있거나 10개를
  초과하면 `ARTIST_INVALID_SOURCE_IDS`로 거부한다.
- 병합 후 source Artist를 삭제하고 target Artist의 `needsReview`를 `true`로 변경한다.
- target의 대표명, `genre`, `instagramUrl`, `imageUrl`은 변경하지 않는다.
- `mergedCount`는 중복을 제거한 실제 source Artist 수다.

### 별칭 처리

- `keepAliases`의 기본값은 `true`다.
- `true`이면 source의 대표명과 기존 alias를 target alias 후보로 이관한다.
- target 대표명과 같은 이름, 이미 사용 중인 Artist 대표명, 이미 존재하는 alias는 추가하지 않는다.
- `false`이면 source 대표명과 alias를 target에 이관하지 않으며 source 삭제와 함께 기존 source alias도
  삭제된다.

### 라인업 이관 및 중복 처리

- source Artist를 참조하는 Lineup의 Artist를 target으로 일괄 변경한다.
- 같은 Festival, day, Artist 조합이 중복되면 가장 작은 `displayOrder`의 Lineup만 남기고 나머지를
  삭제한다.
- `movedAppearances`는 target으로 이관된 Lineup 수, `removedDuplicates`는 이관 후 삭제한 중복
  Lineup 수다.
- Artist가 null인 시크릿 게스트 Lineup은 source ID 조건에 포함되지 않으므로 변경하지 않는다.

### 트랜잭션 및 동시성 제어

- 병합 public 메서드 전체에 `@Transactional`을 적용해 Lineup 이관, 중복 삭제, alias 처리,
  source 삭제, target 갱신을 하나의 트랜잭션으로 수행한다.
- target과 source Artist를 `PESSIMISTIC_WRITE`로 함께 잠근 뒤 검증한다.
- 잠금 조회를 `ORDER BY id`로 고정해 여러 Artist를 잠그는 순서를 일관되게 유지한다.
- 동일 source를 대상으로 한 동시 병합은 첫 요청의 잠금이 해제된 뒤 후속 요청이 다시 조회하게 되며,
  이미 삭제된 source를 확인해 병합을 계속하지 못한다.

## API 계약

`POST /admin/artists/merge`

요청 핵심 필드:

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `targetId` | Long | 남길 Artist ID |
| `sourceIds` | Long[] | 흡수할 Artist ID 목록, 중복 제거 후 1~10개 |
| `keepAliases` | Boolean | source 이름·alias 이관 여부, 생략 시 `true` |

응답 핵심 필드:

| 필드 | 설명 |
| --- | --- |
| `targetId`, `name` | 병합 후 남은 Artist 식별자와 대표명 |
| `mergedCount` | 실제 병합한 중복 제거 source 수 |
| `movedAppearances` | target으로 이관한 Lineup 수 |
| `removedDuplicates` | 이관 후 제거한 중복 Lineup 수 |
| `otherNames` | 병합 후 target alias 목록 |
| `needsReview` | 병합 후 `true` |

## 리뷰 반영 내용

- 동일 source Artist에 대한 동시 병합 경쟁을 막기 위해 target/source Artist 잠금 조회에
  `PESSIMISTIC_WRITE`를 적용했다.
- 여러 Artist 잠금 순서를 ID 오름차순으로 고정했다.
- 이름 중복 확인은 최신 develop의 `findAllByNameIn` 조회와 정리해 병합 코드가 중복 repository
  메서드를 만들지 않도록 반영했다.
- Artist CRUD, Import, Alias 변경, Lineup 변경이 병합과 동시에 실행되는 교차 기능 동시성은 동일
  source 병합 경쟁과 별도 범위로 분리했다.

## 제한사항 및 후속 작업

- 실제 동시 요청을 실행하는 전용 회귀 테스트는 없다. 따라서 동시성 제어는 코드와 잠금 쿼리 반영까지
  확인했으며 동시성 테스트 완료로 기록하지 않는다.
- Artist CRUD, Import, Alias 변경, Lineup 변경 Repository가 병합과 동일한 Artist 잠금 정책을
  사용하도록 정리하는 교차 기능 동시성 작업은 이번 PR 범위가 아니다.
- 이 교차 기능 동시성 작업을 직접 다루는 GitHub Issue는 현재 확인되지 않았으며, 별도 Issue로 후속
  관리 예정이다. 병합 후보 조회 Issue #54와 Import commit Issue #39를 이 후속 작업 번호로 간주하지
  않는다.
