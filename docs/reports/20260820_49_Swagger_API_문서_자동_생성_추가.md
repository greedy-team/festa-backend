### 📌 작업 개요

springdoc-openapi로 API 문서를 코드에서 자동 생성하도록 붙였다. 문서를 여는 것은
`development` 프로파일 하나이며, 프로파일을 지정하지 않으면 닫힌 채로 뜬다.

범위는 설정과 `develop`에 이미 머지된 컨트롤러 문서화까지다. 관리자 아티스트 API는
develop에 없어(#32 진행 중) 이번 범위에서 뺐다.

### 🔍 문제 분석

#### 명세와 구현이 갈려 있고 실물을 확인할 방법이 없다

계약 원본이 노션 문서인데 구현이 바뀔 때마다 사람이 갱신해야 해서 어긋난 자리가 쌓였다.

- 관리자 API 경로에서 `/api` 접두사를 걷어냈다 (#26)
- 아티스트 등록·수정에서 이미지 주소를 요청으로 받지 않기로 했다 (#32)
- 에러 코드 이름 두 개가 명세 표기와 다르다 (`ARTIST_DUPLICATE_NAME`, `ARTIST_INVALID_GENRE_TYPE`)

프론트가 무엇이 진짜인지 확인할 방법이 없었다.

#### 관리자 API를 손으로 시험하기 번거롭다

`/admin/**`은 JWT를 요구한다. curl로 확인하려면 로그인 → 토큰 복사 → 헤더 첨부를
매번 반복해야 한다.

#### 어느 엔드포인트가 어떤 에러 코드를 던지는지 코드에만 있다

에러 응답 네 필드(`errorCode`·`message`·`status`·`instance`)는 #17에서 통일했으나,
엔드포인트별로 어떤 코드가 나오는지는 서비스 코드를 열어야 알 수 있다.

#### 그냥 붙이면 운영 서버에 그대로 공개된다

`SecurityConfig`가 관리자 경로 외에는 `permitAll`이고 `deploy/compose.yaml`이 8080을
직접 노출한다. 그리고 `application.yml`이 하나뿐이라 환경별로 켜고 끌 수단 자체가 없었다.

### ✅ 구현 내용

#### springdoc-openapi 의존성 추가

`build.gradle.kts`에 `org.springdoc:springdoc-openapi-starter-webmvc-ui:3.1.0`을 추가했다.
Spring Boot BOM이 관리하지 않는 의존성이라 버전을 직접 적었고, 다른 직접 지정 의존성(jjwt)과
같은 방식으로 최상단에 변수로 뺐다.

#### 실행 프로파일 분리

공통 `application.yml`에서 문서와 화면을 끄고, 새로 만든 `application-development.yml`에서만 켠다.

```yaml
# application.yml
springdoc:
  api-docs:
    enabled: false
  swagger-ui:
    enabled: false
```

프로파일을 지정하지 않은 실행이 곧 닫힌 상태이므로, 배포 설정을 손대지 않아도 노출되지 않는다.

#### 문서 기본 정보와 인증 스킴

`SwaggerConfig`가 `OpenAPI` 빈으로 제목·설명·버전과 JWT Bearer 인증 스킴을 정의한다.
스웨거 화면의 Authorize에 토큰을 넣으면 이후 요청에 자동으로 붙는다.

#### 컨트롤러 문서화

`AdminAuthController`와 `HostAdminController`에 태그·요약·엔드포인트별 에러 코드를 붙였다.
에러 응답은 기존 `ErrorResponse`를 그대로 참조하므로 문서에 네 필드가 그대로 나온다.

#### 배포 경로에 프로파일 전달

`PROJECT-SPRING-CD.yaml`이 `app.env`에 `SPRING_PROFILES_ACTIVE`를 쓰고 `compose.yaml`이
앱 컨테이너로 넘긴다. 값은 워크플로우가 이미 계산하던 `DEPLOY_ENVIRONMENT`를 그대로 쓴다.

#### 로컬 실행 문서

`README.md`에 기동에 필요한 환경변수 11개를 로컬 예시 값과 함께 표로 정리하고, 로컬
데이터베이스 실행 명령과 스웨거 주소를 적었다.

### 🧭 결정 기록 (ADR)

#### 문서를 여는 것이 아니라 닫는 것을 기본값으로 둔다

`enabled: false`를 공통 설정에 두고 개발 프로파일에서만 켠다. 반대로 두면 프로파일을
빠뜨린 배포가 곧 공개가 된다. 실수의 방향이 안전한 쪽을 향하도록 했다.

#### develop 배포 서버에서는 켜고 운영은 끈다

업계 관행은 운영을 끄고 개발·스테이징을 켜는 것인데, 그 관행에는 개발 서버가 사내망이나
VPN 뒤에 있다는 전제가 깔려 있다. 우리 develop 서버는 인터넷에 8080이 열려 있어 전제가
맞지 않는다.

그럼에도 켜기로 했다. 노출되는 것은 스키마 정보이고 `POST /admin/auth/login`은 스웨거가
없어도 이미 공개돼 있으며 인증 요구는 그대로다. 반대로 끄면 프론트가 문서를 보려고 백엔드를
직접 띄워야 해서 도입 효용이 크게 준다.

Basic 인증을 한 겹 씌우는 선택지도 검토했으나, 로그인 방식이 하나 더 늘어 관리 비용이
MVP 단계의 이득보다 크다고 보고 접었다. **실제 사용자가 붙기 전에 다시 판단한다.**

#### JWT 스킴을 전역 보안 요구사항으로 걸지 않는다

`OpenAPI`에 `addSecurityItem`으로 전역 요구사항을 걸면 모든 엔드포인트에 자물쇠가 붙는다.
인증이 필요한 것은 `/admin/**`뿐이라 공개 API까지 인증이 필요한 것처럼 그려져 문서가 실제
규칙과 어긋난다. 스킴은 `components`에 등록만 하고, 요구사항은 관리자 컨트롤러에
`@SecurityRequirement`로 개별로 붙였다. 로그인 엔드포인트는 열린 채로 뒀다.

#### local과 development 프로파일을 나누지 않는다

로컬 실행용과 개발 배포용을 따로 두는 구성을 검토했으나, 지금 프로파일이 통제하는 것이
문서 on/off 하나뿐이라 나누면 같은 설정이 두 파일에 복사된다. 통제 대상이 갈리는 시점에
나눈다.

#### 시큐리티 설정은 건드리지 않는다

현재 관리자 경로 외에는 전부 열려 있어 스웨거 경로가 이미 접근 가능하고, 프로파일로 꺼두면
경로 자체가 등록되지 않아 404다. 공개 여부를 통제하는 지점을 프로파일 하나로 모았다.
시큐리티에도 경로 규칙을 넣으면 통제 지점이 둘로 갈린다.

#### 테스트는 노출 여부 하나만 지킨다

구현 과정에서 문서 제목·태그·인증 스킴·에러 스키마를 검증하는 테스트를 함께 만들었으나
최종적으로 지웠다. 그 검사들은 **방금 작성한 문자열이 그대로 있는지**를 묻거나
**springdoc이 제 일을 하는지**를 묻는 것이라, 깨져도 알려주는 것이 없고 태그 이름을 바꿀
때마다 함께 고쳐야 한다. `@SpringBootTest`라 컨텍스트 기동에만 13초가 들었다.

남긴 것은 「프로파일 없이 뜨면 문서를 내주지 않는다」 하나다. 이것은 라이브러리 동작이 아니라
관리자 API 명세가 인터넷에 공개되는지를 지키며, 공통 설정에 `enabled: true`가 잘못 들어가면
아무 에러 없이 열리는 조용한 실패다.

### 🔧 주요 변경사항 상세

#### 프로파일이 정해지는 경로

배포 워크플로우가 브랜치에 따라 `development`(develop) 또는 `production`(main)을 계산하고,
그 값이 `app.env`를 거쳐 컨테이너의 `SPRING_PROFILES_ACTIVE`로 들어간다. `production`에는
프로파일별 설정 파일이 없으므로 공통 설정의 꺼짐이 그대로 적용된다.

`compose.yaml`에서는 기본값을 비워 뒀다. 값이 없으면 프로파일 없이 뜨고, 그것이 곧 닫힌 상태다.

#### 문서에 실리는 에러 코드

엔드포인트마다 실제로 던지는 도메인 에러 코드를 응답 설명에 적었다. 주최 삭제의 `409`는
`HOST_HAS_FESTIVALS`, 수정의 `404`는 `HOST_NOT_FOUND`처럼 코드 이름을 그대로 노출해
프론트가 분기할 대상을 문서에서 바로 찾도록 했다.

토큰 관련 401(`UNAUTHORIZED` / `TOKEN_EXPIRED`)은 모든 관리자 엔드포인트에 공통이라
메서드마다 반복하지 않고 태그 설명에 적었다.

### 📌 참고사항

#### 범위 밖으로 둔 것

- **관리자 아티스트 API 문서화** — #32가 develop에 머지되지 않아 이번 범위에서 뺐다.
  머지 후 별도로 붙인다
- **노션 API 명세 동결** — 계약 원본을 코드로 옮기기로 했다. 노션 문서 상단에 동결 안내를
  남기는 것은 저장소 밖 작업이라 이 변경에 포함되지 않는다

동결에는 단서가 붙는다. 스웨거는 구현된 것만 비추는데 MVP 1차 엔드포인트 25개 중 지금
구현된 것은 둘이다. 동결한 노션 문서가 나머지 계약의 유일한 기록이므로, 동결은 갱신 중단이며
폐기가 아니다. 미구현 API를 구현할 때는 그 문서를 근거로 삼는다.

#### 작업 중 발견한 별건

존재하지 않는 경로로 요청하면 404가 아니라 500(`INTERNAL_SERVER_ERROR`)이 응답된다.
`GlobalExceptionHandler`의 `@ExceptionHandler(Exception.class)`가 Spring MVC의
경로 미해결 예외까지 삼키기 때문이다. `CommonErrorCode`에 `RESOURCE_NOT_FOUND`가 정의만 되고
아무도 던지지 않는다. `METHOD_NOT_ALLOWED`도 같은 상태로 보인다. 별건이라 이 변경에
포함하지 않았다.

#### 환경변수 값에 관하여

README 표의 값은 전부 로컬 전용 임의 값이다. 배포 환경의 실제 값은 GitHub Environments에
있으며 저장소에는 두지 않는다. `ADMIN_INITIAL_USERNAME`과 `ADMIN_INITIAL_PASSWORD`는 함께
넣거나 함께 비워야 하고, 둘 다 비우면 관리자 계정 시딩을 건너뛴다.
