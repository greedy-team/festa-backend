### 구현 범위

#### 관리자 Artist API

| 기능 | Method | 경로 | 동작 |
| --- | --- | --- | --- |
| 등록 | POST | `/admin/artists` | 대표명, 별칭, 장르, Instagram URL을 받아 아티스트 생성 |
| 목록 | GET | `/admin/artists` | 검토 상태·검색어·장르 필터, 정렬, 페이지네이션 적용 |
| 수정 | PATCH | `/admin/artists/{id}` | 전달된 필드만 부분 수정하고 별칭은 요청 상태에 따라 유지 또는 교체 |
| 삭제 | DELETE | `/admin/artists/{id}` | Lineup이 전혀 없는 아티스트만 삭제 |

별도의 단건 GET API는 이 작업 범위에 포함하지 않았다. 등록·수정 응답과 목록 항목은 동일한 `ArtistResponse` 형식을 사용한다.

#### 계층별 역할

- `ArtistAdminController`
  - `/admin/artists` 요청을 등록·목록·수정·삭제 서비스로 전달한다.
  - 목록의 `needsReview`, `q`, `genre`, `sort`, `page`, `size`를 바인딩한다.
  - `genre`와 `sort` 문자열을 열거값으로 변환하고 잘못된 값에는 아티스트 도메인 오류를 반환한다.
- `ArtistService`
  - 이름·별칭 정규화와 중복 검증, 부분 수정, 별칭 동기화, 삭제 가능 여부를 담당한다.
  - 목록 응답에 필요한 별칭을 아티스트 ID 묶음으로 조회해 N+1 조회를 피한다.
  - 등록 시 `needsReview=false`, `imageUrl=null`로 저장한다.
- `ArtistRepository`
  - 이름 중복 확인, 목록 검색·필터·집계, 표시용 출연 횟수와 삭제 판정용 Lineup 수를 제공한다.
- `ArtistAliasRepository`
  - 별칭 조회, 중복 확인, 차집합 기반 추가·삭제와 아티스트 삭제 전 별칭 정리를 담당한다.
- DTO
  - `ArtistCreateRequest`: `name`, `otherNames`, `genre`, `instagramUrl`
  - `ArtistUpdateRequest`: `name`, `otherNames`, `genre`, `instagramUrl`, `needsReview`
  - `ArtistResponse`: `artistId`, `name`, `otherNames`, `genre`, `imageUrl`, `instagramUrl`, `appearanceCount`, `needsReview`, `createdAt`
  - `ArtistSortType`: `CREATED_DESC`, `APPEARANCES`, `NAME`

### 목록 검색·필터·정렬·페이지네이션

- 검토 상태: `needsReview`가 전달되면 해당 상태만 조회한다.
- 검색어: 대표명과 모든 별칭을 대소문자 구분 없이 부분 검색한다. 별칭 여러 개가 일치해도 아티스트 행은 중복되지 않는다.
- 장르: `genre`가 전달되면 해당 장르만 조회한다.
- 정렬:
  - `CREATED_DESC`: 등록일 내림차순, 같은 값은 ID 오름차순
  - `APPEARANCES`: 표시용 출연 횟수 내림차순, 같은 값은 ID 오름차순
  - `NAME`: 대표명 오름차순, 같은 값은 ID 오름차순
- 페이지: 기본 `page=0`, `size=20`; page는 0 이상, size는 1~50만 허용한다.
- 검색어 길이는 trim 기준 50자 이하만 허용한다.

### 등록·조회·수정·삭제 정책

#### 등록

- 대표명은 앞뒤 공백을 제거한 뒤 검증하고 저장한다.
- null, 빈 문자열, 공백-only 대표명과 100자를 초과하는 대표명은 `ARTIST_INVALID_NAME`으로 거부한다.
- 별칭은 null 제거, trim, 공백 값 제거, 대표명과 같은 값 제거, 요청 내 중복 제거 순으로 정규화한다.
- 대표명은 기존 `Artist.name`과 `ArtistAlias.name` 양쪽에서 중복을 확인한다.
- 별칭은 기존 `Artist.name`과 `ArtistAlias.name` 양쪽에서 중복을 확인한다.
- Instagram URL은 앞뒤 공백을 제거한다. 등록 요청의 null·빈 문자열·공백-only 값은 null로 저장한다.
- 이미지 URL은 요청에서 받지 않으며 관리자 등록 결과는 null이다.

#### 목록 및 응답

- 목록은 아티스트와 표시용 `appearanceCount`를 함께 조회한다.
- 별칭은 현재 페이지의 아티스트 ID를 모아 한 번에 조회한다.
- 생성 응답의 `appearanceCount`는 0이다.
- 수정 응답의 `appearanceCount`는 목록과 같은 정책으로 다시 계산한다.

#### 수정

- 요청 필드가 null이거나 미전송이면 기존 값을 유지한다.
- 대표명은 null과 빈 입력을 구분한다.
  - null/미전송: 기존 이름 유지
  - `""`: `ARTIST_INVALID_NAME`
  - `"   "`: `ARTIST_INVALID_NAME`
  - `" BTS "`: `"BTS"`로 trim한 뒤 중복 검증 및 저장
- 대표명 변경 시 다른 Artist의 대표명·별칭과 충돌하면 `ARTIST_DUPLICATE_NAME`으로 거부한다.
- name-only PATCH에서 새 대표명이 자기 별칭과 같으면 해당 별칭을 삭제한다.
- name과 otherNames를 함께 보내면 정규화된 최종 별칭 목록에서 새 대표명과 같은 값을 제외한다.
- `otherNames`가 null/미전송이면 기존 별칭을 유지한다.
- `otherNames=[]`이면 별칭을 모두 삭제한다.
- 별칭 배열이 전달되면 차집합으로 현재 별칭을 최종 배열 상태와 동기화한다.
- Instagram URL은 null/미전송이면 유지한다. 전달된 값은 trim하며, trim 결과가 빈 문자열이면 null로 변경한다.

#### 삭제

- 아티스트가 없으면 `ARTIST_NOT_FOUND`를 반환한다.
- 발행 여부나 축제 종료 여부와 관계없이 Lineup이 하나라도 존재하면 `ARTIST_HAS_APPEARANCES`로 삭제를 거부한다.
- Lineup이 전혀 없으면 별칭을 먼저 삭제하고 flush한 뒤 아티스트를 삭제한다.

### 리뷰 반영 내용

#### 대표명과 alias 교차 중복 방지

대표명 검증이 `Artist.name`만 확인하던 문제를 수정했다. 등록 및 수정 시 `ArtistAlias.name`도 함께 조회하므로 기존 별칭과 같은 대표명을 새로 만들 수 없다. 별칭 추가 시에도 기존 대표명과 기존 별칭을 모두 확인한다.

#### 대표명 변경과 자기 alias 충돌 방지

대표명만 수정할 때 새 대표명과 같은 자기 별칭을 삭제한다. 대표명과 별칭을 함께 수정할 때는 별칭 정규화 단계에서 대표명과 같은 값을 제외하고 차집합 동기화하므로 대표명과 alias가 동일하게 남지 않는다.

#### 이름 정규화와 공백-only PATCH 회귀 수정

등록과 수정 모두 대표명의 앞뒤 공백을 제거한다. PATCH에서는 null/미전송과 빈 입력을 분리해 처리한다. 따라서 `name=""`와 `name="   "`은 `ARTIST_INVALID_NAME`으로 거부하고, null/미전송만 기존 이름 유지로 처리한다.

#### Instagram URL 정규화

등록 시 null·빈 문자열·공백-only 값을 null로 정규화한다. 수정 시에는 값이 전달된 경우 먼저 trim하고, trim 결과가 빈 문자열이면 엔티티가 null로 변경한다. null/미전송은 기존 값을 유지한다.

#### appearanceCount 정책 통일

표시용 출연 횟수는 다음 조건을 모두 만족하는 축제의 Lineup만 집계한다.

- `festival.publishedAt IS NOT NULL`
- `festival.endDate < CURRENT_DATE`

목록의 `appearanceCount`, `APPEARANCES` 정렬, 수정 후 단건 응답의 `appearanceCount`가 모두 같은 조건을 사용한다. 삭제 제한은 표시용 집계와 분리해 모든 Lineup을 대상으로 판단한다.

#### Swagger 테스트 컨텍스트 호환

최신 develop 병합으로 `ArtistService`가 `SwaggerDisabledByDefaultTest`의 ApplicationContext에 포함되면서 `ArtistRepository`와 `ArtistAliasRepository`가 없다는 오류가 발생했다. 테스트에 두 repository를 `@MockitoBean`으로 추가해 데이터소스·JPA 자동 설정을 제외한 context에서도 서비스 의존성이 충족되도록 수정했다. 이 문제는 Docker/Testcontainers와 무관한 Spring context 구성 문제이며 최종 상태에서 해결됐다.

### 데이터 및 비즈니스 정책

#### 대표명·별칭 유일성

- 대표명은 모든 Artist 대표명과 모든 alias를 합친 이름 공간에서 유일해야 한다.
- alias 역시 모든 Artist 대표명과 모든 alias를 합친 이름 공간에서 유일해야 한다.
- 같은 요청 안의 중복 alias와 대표명과 같은 alias는 저장하지 않는다.
- 현재 비교는 저장된 문자열 기준이며 대소문자를 구분한다.

#### PATCH 값의 의미

| 입력 | name | otherNames | instagramUrl |
| --- | --- | --- | --- |
| null/미전송 | 기존 값 유지 | 기존 목록 유지 | 기존 값 유지 |
| 빈 문자열 | 잘못된 이름으로 거부 | 해당 없음 | null로 변경 |
| 공백-only | 잘못된 이름으로 거부 | 공백 alias 제거 | null로 변경 |
| 일반 값 | trim 후 검증·저장 | 각 값 trim 후 최종 목록으로 동기화 | trim 후 저장 |

#### appearanceCount 정의

현재 날짜보다 종료일이 이전이고 발행 시각이 존재하는 축제의 Lineup 수다. 예정·진행 중 축제와 미발행 축제는 관리자 화면에 표시하는 출연 횟수에 포함하지 않는다.

#### 삭제 조건

표시용 `appearanceCount`가 0이더라도 미발행 또는 미래 축제 Lineup이 존재하면 삭제할 수 없다. 삭제 가능 여부는 모든 Lineup 존재 여부로 판단한다.

### 제한사항 및 후속 작업

- 아티스트 병합과 병합 후보 조회는 PR #45 범위가 아니며 별도 Issue #36에서 다룬다.
