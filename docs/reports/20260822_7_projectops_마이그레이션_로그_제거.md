### 📌 작업 개요

템플릿 통합(`npx projectops`) 1회 실행 기록인 `docs/projectops/migration/`을 삭제했다.
가이드가 지시한 실행 후 체크리스트는 이미 전부 처리됐고, 통합 상태는 `version.yml`이 들고 있어
이 폴더가 더는 참조되지 않는 상태였다.

### 🎯 구현 목표

- 쓰임이 끝난 1회성 실행 기록 제거
- 통합 상태의 단일 출처를 `version.yml`로 정리

### ✅ 구현 내용

#### 마이그레이션 기록 폴더 삭제

- **파일**: `docs/projectops/migration/PROJECTOPS-MIGRATION-GUIDE.md` (85줄), `docs/projectops/migration/20260802_141915_vnew_to_v4.2.44.jsonl` (37줄)
- **변경 내용**: 두 파일 삭제
- **이유**: 가이드는 마법사가 실행마다 append하는 이력 문서이고, JSONL은 파일별 치환 전후 기록이다.
  통합은 2026-08-02 1회뿐이었고 그 실행이 남긴 체크리스트(Docker 워크플로우 제거, 브랜딩 정리, 커맨드 정리)는 모두 처리됐다

삭제 전 확인한 것 — 워크플로우와 스크립트에서 `docs/projectops`를 참조하는 곳은 0건이다.
재통합 시 마법사가 읽는 것은 이 폴더가 아니라 `version.yml`의 `template.source` / `version` / `mode` / `integrated_date`다.

### 🧭 결정 기록 (ADR)

#### 이력을 보관하지 않고 삭제

- **문제**: 1회 실행 기록을 남겨둘지 지울지
- **선택**: 삭제. 통합 상태는 `version.yml`이 갖고 있고, 다음 `npx projectops` 실행은 자기 로그를 새로 만든다
- **대안**:
  - 폴더를 유지하고 README로 "참고용"이라 표시 — 참조하는 곳이 0건인 문서를 유지 비용만 남기고 두게 된다
  - `.gitignore`에 넣어 로컬에만 둠 — 이미 커밋된 파일이라 ignore가 듣지 않는다
- **트레이드오프**: 통합 당시 터미널 원문(포렌식용 Layer 3)은 되살릴 수 없다. Git 이력에는 남는다

### 🧪 테스트 및 검증

- `docs/projectops` 문자열 참조 검색 결과 0건 확인
- 빌드·배포·런타임에 관여하지 않는 문서라 별도 검증 없음

### 📌 참고사항

- 이슈는 `*.log`(통합 당시 터미널 원문)도 삭제 대상으로 적었으나, 실제 저장소에는 `.log` 파일이 없어
  삭제된 것은 가이드와 JSONL 두 개다. 저장소 루트 `.gitignore`에 `*.log`가 이미 있어 애초에 커밋되지 않았던 것으로 보인다
- 배포(CD)는 레포별로 직접 구성하므로 템플릿이 남긴 배포 관련 기록도 함께 사라졌다. 현재 CD는 별도 이슈에서 구성한 것이다
