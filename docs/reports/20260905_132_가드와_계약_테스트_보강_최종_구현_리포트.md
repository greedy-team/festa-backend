# 가드와 계약 테스트 보강 최종 구현 리포트

## 작업 개요

Issue #132와 PR #133은 이름 중복 검사, PATCH 역직렬화, 초기 관리자 시딩, 아티스트 병합의 검증 공백을 메웠다. 기존 프로덕션 동작을 테스트로 드러내고 회귀를 잡는 작업이다.

최종 PR head `b3f2ee8802a7018fb2538bf6b32c5da42c7d66fa`는 develop merge commit `11055450d8f10090365fd4b46dcd805048419610`으로 병합됐다. 머지 결과의 파일 내용은 최종 head와 동일하다. 선행 PR #131의 픽스처 변경을 제외한 이번 구현은 테스트 10파일 `+577/-4`다.

- 관련 Issue: [#132](https://github.com/greedy-team/festa-backend/issues/132)
- 관련 PR: [#133](https://github.com/greedy-team/festa-backend/pull/133)
- 보고서 파일: `docs/reports/20260905_132_가드와_계약_테스트_보강_최종_구현_리포트.md`

## 문제 분석

이름 중복 쿼리의 핵심은 수정 대상 자신을 제외하는 것이다. 서비스 mock만으로 중복 예외를 확인하면 실제 파생 쿼리가 자기 자신을 중복으로 잡는 회귀를 놓친다. 기존 테스트에는 해당 메서드를 직접 검증하는 자리가 없었다.

PATCH 계약 테스트는 Jackson 2 기본 매퍼를 사용했지만 애플리케이션은 Jackson 3와 `JacksonCoercionConfig`를 사용했다. 장르의 생략과 null은 검증하면서 설정의 존재 이유인 빈 문자열은 다루지 않았다. 기존 설정 테스트도 클래스를 직접 `@Import`해 설정 탐색이 끊기는 문제까지 확인할 수 없었다.

`AdminAccountSeeder.run()`의 시딩·건너뛰기·기동 실패 분기와 `ArtistMergeService`의 null target 가드도 테스트가 없었다. 이슈의 525개 테스트라는 수치는 작성 당시 집계이며, 최종 CI 규모는 아래에 별도로 기록한다.

## 최종 계약

| 대상 | 이번 테스트가 확인하는 기존 동작 |
| --- | --- |
| 이름 중복 쿼리 | 자기 이름은 false, 다른 대상의 이름은 true, 없는 이름은 false |
| 별칭 중복 쿼리 | 같은 아티스트의 별칭은 제외하고 다른 아티스트의 별칭은 중복으로 판정 |
| 수정 중복 오류 | `HOST_DUPLICATE_NAME`, `ARTIST_DUPLICATE_NAME`, `ARTIST_DUPLICATE_ALIAS`; HTTP 상태는 기존 409 |
| Artist PATCH의 `genre=""` | Jackson이 null로 읽고 서비스·엔티티는 기존 장르 유지 |
| Festival DTO의 enum `""` | `externalVisitor`·`verification`·`ticketType`이 null로 역직렬화 |
| 초기 관리자 | 설정 누락 조합은 실패 또는 건너뛰기, 기존 계정은 저장하지 않음, 신규 계정은 BCrypt 해시로 저장 요청 |
| 병합 target 누락 | 유효한 source 목록과 null target에 `ARTIST_INVALID_TARGET_ID`; 기존 HTTP 상태는 400 |
| 운영 코드·외부 계약 | `src/main`, API 경로·DTO·Swagger·ErrorCode·DB 스키마·쿼리·의존성 변경 없음 |

빈 문자열이 DTO에서 null이 되는 것과 DB 값을 비우는 것은 다른 단계다. 특히 Artist 장르는 빈 문자열을 보내도 삭제되지 않는다. Festival의 필수 날짜가 null로 역직렬화된다고 수정 요청이 성공하는 것도 아니다. 서비스의 필수값 검증은 그대로 적용된다.

## 구현 내용

### PostgreSQL에서 자기 제외 쿼리를 검증한다

`ArtistRepositoryDuplicateNameTest` 6건과 `HostRepositoryDuplicateNameTest` 3건을 신설했다. 두 클래스는 `@DataJpaTest`, `PostgresTestSupport`, `@AutoConfigureTestDatabase(replace = NONE)`을 사용한다. 엔티티를 persist하고 `flush()`·`clear()`한 뒤 실제 Repository를 호출한다.

Artist와 Host의 `existsByNameAndIdNot`는 자기 이름·타인 이름·없는 이름을 각각 확인한다. `ArtistAliasRepository.existsByNameAndArtistIdNot`도 자기 별칭·타인 별칭·없는 별칭으로 나눠 확인한다. 별칭의 제외 대상이 별칭 행 id가 아니라 소유 아티스트 id라는 점을 검증한다.

### 실제 서비스의 중복 거부와 정상 수정 경로를 보강한다

`ArtistAdminServiceTest`에 네 경로를 추가했다. 수정할 대표명이 다른 아티스트의 대표명 또는 별칭과 겹치면 `ARTIST_DUPLICATE_NAME`, 추가할 별칭이 다른 대표명 또는 별칭과 겹치면 `ARTIST_DUPLICATE_ALIAS`다. `||`의 양쪽을 각각 테스트하며, 이름 거부에서는 기존 이름 유지, 별칭 거부에서는 `saveAll`·`deleteAll` 미호출을 확인한다.

`HostAdminServiceTest`에는 중복 이름 거부와 이름을 유지한 채 다른 필드를 바꾸는 성공 사례를 추가했다. 합계 6건은 **거부 5건과 성공 1건**이다. Repository는 반환값을 stub하고 서비스는 실물을 호출한다. 서비스 mock이 무조건 예외를 던지는 테스트가 아니다. 이 단위 테스트가 DB rollback까지 검증하는 것은 아니다.

### PATCH 매퍼와 설정 배선을 각각 검증한다

`support/AppJsonMapper`는 Jackson 3의 `JsonMapper.Builder`에 실제 `JacksonCoercionConfig.customize()`를 적용한다. `ArtistAdminPatchContractTest`와 `HostAdminPatchContractTest`가 이 헬퍼를 사용하도록 바꿨다. 설정을 테스트 코드에 재구현하지 않는다.

Artist 테스트에는 이름과 `genre=""`를 담은 JSON을 실제 `ArtistUpdateRequest`로 읽고, DTO의 genre가 null이며 서비스 응답은 기존 `DANCE`를 유지하는 사례를 추가했다. 기존 생략·null·공백 문자열 테스트도 새 매퍼로 실행한다.

`JacksonCoercionWiringTest`는 `@SpringBootTest`가 조립한 매퍼를 주입받는다. `JacksonCoercionConfig`를 직접 `@Import`하지 않아 설정 탐색과 customizer 적용을 함께 확인한다. DB 관련 자동설정은 제외하고 Repository와 JPA metamodel은 mock으로 대체해 이 클래스 자체는 Docker를 요구하지 않는다.

배선 테스트 4건은 Artist 장르, Festival enum 3개, Festival 날짜·시각·숫자, 문자열 필드의 빈 문자열을 확인한다. 비문자열의 빈 문자열은 null로, `venueName`의 빈 문자열은 그대로 도착한다. HTTP 요청부터 인증·서비스·DB까지 연결한 통합 테스트가 아니라 실제 컨텍스트의 역직렬화 테스트다.

### 초기 관리자 시딩 분기와 실제 BCrypt를 확인한다

`AdminAccountSeederTest`는 Repository를 mock으로 두고 실제 `BCryptPasswordEncoder`를 사용한다. 다섯 분기를 7회 실행으로 검증한다.

- 아이디만 있으면 비밀번호 설정 누락으로 실패한다.
- 비밀번호만 있으면 아이디 설정 누락으로 실패한다. 공백뿐인 아이디도 별도 확인한다.
- 둘 다 빈 문자열이거나 공백뿐이면 조회·저장 없이 건너뛴다.
- 같은 아이디가 존재하면 저장하지 않는다.
- 신규 계정이면 저장 인자를 capture해 아이디, 원문과 다른 해시, 실제 인코더의 `matches()` 결과를 확인한다.

실제 BCrypt 검증은 저장된 문자열이 로그인 검증에 사용할 수 있는 해시인지 확인한다. 실제 admin_user INSERT나 애플리케이션 기동 전 과정을 검증하는 테스트로 확대 해석하지 않는다.

### null target 병합 오류를 확인한다

`ArtistMergeServiceTest`의 기존 PostgreSQL 구성에 1건을 추가했다. 실제 아티스트를 저장하고 sourceIds에 넣은 뒤 targetId를 null로 전달한다. 실제 서비스가 `ARTIST_INVALID_TARGET_ID`를 던지는지 확인한다. source 목록은 유효하게 준비해 다른 입력 가드에서 먼저 실패하지 않도록 했다.

## 결정 기록 (ADR)

### 쿼리와 서비스의 책임을 다른 층에서 검증한다

- **문제**: 서비스 mock 테스트만으로는 파생 쿼리의 자기 제외 의미를 확인할 수 없다.
- **선택**: 쿼리는 실제 PostgreSQL에서, 중복 판정 후 거부는 실제 서비스와 Repository mock으로 검증한다.
- **대안**: 모든 검증을 서비스 단위 테스트로만 구성하면 쿼리 회귀를 놓친다.
- **트레이드오프**: Repository 테스트에는 Docker가 필요하다. 기존 컨테이너 지원 클래스를 재사용한다.

### 수동 구성 매퍼와 애플리케이션 배선 테스트를 함께 둔다

- **문제**: 빠른 계약 테스트가 설정을 직접 호출하면 설정 클래스가 애플리케이션에서 빠져도 통과할 수 있다.
- **선택**: PATCH 테스트는 실제 customizer를 재사용하고, 별도 컨텍스트 테스트에서 자동 탐색을 검증한다.
- **대안**: 기존 `@Import` 테스트만 유지하면 배선 누락을 확인하지 못한다.
- **트레이드오프**: 컨텍스트 구동 비용과 mock 빈 구성이 추가된다. DB 검증 책임은 PostgreSQL 테스트에 남긴다.

그 밖에 API나 운영 정책을 새로 결정한 사항은 없다. BCrypt 실물 사용과 시딩 분기 검증은 이슈의 명시 요구를 따른다.

## 리뷰 논의 및 반영 내용

머지 전 리뷰에서는 Controller → DTO → Service → Repository/Entity와 예외 응답을 대조했고 blocking·non-blocking 코드 finding은 없었다. 해당 리뷰는 대화로 전달됐으며 GitHub 리뷰 댓글로 등록하지 않았다. 최종 머지본은 검토한 head와 파일 내용이 같다.

본문과 실제 코드가 다른 집계는 이 리포트에서 바로잡는다. PR의 `+676/-4` 대신 최종 diff `+577/-4`, 서비스 거부 6건 대신 거부 5건·정상 수정 1건을 사용한다. 이슈가 중복 오류를 400으로 설명한 부분도 실제 ErrorCode·Swagger의 409와 구분한다. Issue·PR 본문 자체는 수정하지 않는다.

## 기존 결정과의 관계

실제 DB가 파생 쿼리를 실행하도록 하고, 설정 클래스를 직접 가져오는 테스트와 애플리케이션 배선 테스트를 분리했다. 기존의 “프레임워크가 연결하는 동작은 실물로 확인한다”는 테스트 원칙을 따른다.

PATCH 빈 문자열의 역직렬화는 기존 설정을 확인한 것이며 새로운 입력 정책을 도입하지 않았다. PR 본문이 제기한 문서와 실제 동작의 불일치를 해결하거나 문서상의 정책을 변경한 작업도 아니다.

관리자 인증, requestId·admin MDC, 접속 기록, WARN 파일 보관, commit 이후 성공 로그, import·publish·UNKNOWN 관련 운영 구현은 이번 diff에 포함되지 않는다.

## 남은 후속 사항

- 가드별 제거 실험의 조건과 결과가 확보되면 검증 증빙을 보완할 수 있다. 현재 CI 통과만으로 모든 가드의 변이 검증 완료를 주장하지 않는다.
- enum 빈 문자열과 비우기 정책의 문서 정합성은 별도 판단이 필요하다. 현재 Artist의 빈 장르는 기존 값 유지라는 동작을 정확히 구분해야 한다.
- PR이 보고만 한 초기 관리자 username trim, Host 생성·수정의 검증 순서, null 제외 id 쿼리의 경계는 이번 테스트 보강에서 수정하지 않았다.
- 머지 후 배포 성공 여부는 위 CD 실행의 최종 결과로 별도 확인해야 한다.
