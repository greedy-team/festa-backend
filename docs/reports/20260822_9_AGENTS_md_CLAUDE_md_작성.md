### 📌 작업 개요

에이전트가 세션 시작 시 읽는 지침 파일을 만들었다.
도구 중립 표준인 `AGENTS.md`에 내용을 두고, `CLAUDE.md`는 그것을 import하는 얇은 파일로 뒀다.
협업 규칙(`TEAM-CONVENTIONS.md`)과 작업 커맨드(`.claude/commands/`)도 이 작업에서 함께 들어갔다.

### 🎯 구현 목표

- 세션 시작 시 프로젝트 성격·셋업 명령·제약을 읽을 수 있는 진입점 마련
- 같은 규칙이 두 곳에 복사되지 않는 구조로 배치

### 🔍 왜 필요했나

지침 파일이 없으면 에이전트는 프로젝트를 모른 채 시작한다. 이미 겪은 문제들이 그 결과였다.

- README가 `npm run dev`를 안내해 pnpm 규칙과 충돌
- 환경변수를 GitHub Secrets에 넣으면 앱에 들어가지 않는다는 것을 모름
- `main` 직접 푸시가 곧 배포라는 것을 모름

### ✅ 구현 내용

#### 에이전트 지침 진입점

- **파일**: `AGENTS.md` (116줄), `CLAUDE.md` (15줄)
- **변경 내용**: 실제 내용은 `AGENTS.md`에만 두고, `CLAUDE.md`는 이를 import하는 형태로 작성
- **이유**: 같은 규칙을 두 파일에 적으면 반드시 어긋난다. 도구가 늘어나도 내용 파일은 하나로 유지된다

#### 협업 규칙 문서

- **파일**: `TEAM-CONVENTIONS.md` (218줄)
- **변경 내용**: 브랜치·커밋·PR·릴리스 규칙을 한 문서로 정리
- **이유**: `AGENTS.md`가 규칙 전문을 담지 않고 **가리키기만** 하도록 하기 위한 대상 문서다

#### 작업 커맨드와 규칙

- **파일**: `.claude/commands/` 7종 — `issue.md`(257줄), `report.md`(438줄), `pr-description.md`(232줄),
  `commit.md`(139줄), `rp.md`(129줄), `issue-branch.md`(74줄), `cr.md`(46줄)
- **파일**: `.claude/rules/coding-principles.md` (124줄)
- **변경 내용**: 이슈 생성·보고서·PR 본문·커밋·코드리뷰 커맨드와 코딩 원칙 추가
- **이유**: 반복되는 작업의 절차를 문서 하나로 고정해, 사람이 하든 에이전트가 하든 같은 산출물이 나오게 한다

#### 도구 중립 스킬 포인터

- **파일**: `.agents/skills/{commit,cr,issue-branch,issue,pr-description,report,rp}/SKILL.md` (각 9줄)
- **변경 내용**: 각 커맨드로 연결되는 9줄짜리 포인터 파일
- **이유**: `.claude/` 경로를 읽지 않는 도구에서도 같은 절차를 찾아갈 수 있게 한다. 내용은 복사하지 않고 가리키기만 한다

### 🧭 결정 기록 (ADR)

#### 내용은 `AGENTS.md`에만, `CLAUDE.md`는 import 한 줄

- **문제**: 도구마다 다른 이름의 지침 파일을 요구하는데 내용을 어디에 둘지
- **선택**: `AGENTS.md`가 유일한 내용 파일. `CLAUDE.md`는 import만 한다
- **대안**:
  - 양쪽에 전문 복사 — 한쪽만 고쳐지는 순간 어긋난다
  - `CLAUDE.md`에 내용을 두고 `AGENTS.md`가 참조 — 도구 중립 표준이 특정 도구 파일에 종속된다
- **트레이드오프**: import를 지원하지 않는 도구에서는 `CLAUDE.md`가 빈 껍데기로 보인다
- ⭐ **볼트 승격 권장** — 두 레포와 이후 모든 에이전트 도구에 적용되는 배치 규칙이다

#### 규칙을 지침 파일에 옮겨 적지 않고 가리키기만 함

- **문제**: `TEAM-CONVENTIONS.md`와 `.claude/commands/`가 이미 규칙을 담고 있는데 `AGENTS.md`에 무엇을 적을지
- **선택**: 링크만. `AGENTS.md`는 "어디를 보라"만 말한다
- **대안**: 요약을 적어둠 — 요약과 원문이 갈라지고, 갈라진 것을 아무도 눈치채지 못한다
- **트레이드오프**: 에이전트가 파일 하나를 더 열어야 한다

### 🧪 테스트 및 검증

문서·설정 파일만 추가하므로 빌드·배포·런타임에 영향이 없다.
검증은 새 세션에서 `AGENTS.md`가 실제로 읽히고 커맨드가 동작하는지로 갈음했다.

### 📌 참고사항

- 이슈 제목은 `AGENTS.md` · `CLAUDE.md` 두 파일만 가리키지만, 실제로는 18개 파일이 함께 들어갔다.
  가리킬 대상(`TEAM-CONVENTIONS.md`, `.claude/commands/`)이 없으면 지침 파일이 링크만 남고 비게 되기 때문이다
- `.github/scripts/`와 워크플로우는 `npx projectops` 업데이트 시 덮어써진다. 설정을 코드 기본값이 아니라
  `version.yml`에 두는 규칙은 `AGENTS.md`에 기록돼 있다
