### 📌 작업 개요

아티스트·라인업·임포트 도메인의 JPA 엔티티 6개와 Flyway 마이그레이션 추가.
축제·주최 스키마(#15, #22) 위에 크롤러 산출물 적재에 필요한 나머지 테이블을 얹는다.

**보고서 파일**: `docs/reports/20260819_19_아티스트_라인업_임포트_엔티티와_스키마_추가.md`

### 🎯 구현 목표

- `Artist` · `ArtistAlias` · `Lineup` — 아티스트 도메인과 축제 라인업
- `ImportBatch` · `ImportCommitRow` — CSV 임포트 배치와 행 단위 감사 기록
- `AdminUser` — 임포트 배치의 업로더 참조 대상
- 위 6개 테이블의 Flyway 마이그레이션 작성
- `ddl-auto: validate` 통과 (기동 실패 없이 `develop` 머지 가능한 상태)

### ✅ 구현 내용

#### 아티스트 도메인 엔티티

- **파일**: `src/main/java/com/greedy/festa/artist/entity/Artist.java`, `ArtistAlias.java`, `ArtistGenre.java`
- **변경 내용**: `Artist`는 `BaseEntity` 상속. `genre` · `imageUrl` · `instagramUrl`은 nullable, `needsReview`는 필수.
  `ArtistAlias.name`은 `(artist_id, name)` 복합이 아니라 전역 `UNIQUE`이며 `Artist` 쪽 역방향 컬렉션을 두지 않음.
  `ArtistGenre`는 `HIPHOP` · `BALLAD_RNB` · `BAND` · `DANCE` 4종
- **이유**: 같은 별칭이 여러 아티스트에 매칭되면 임포트가 어느 쪽에 붙일지 모호해진다. 전역 유일이면 매칭이 결정적이다 (DEC-0074)

#### 라인업 엔티티

- **파일**: `src/main/java/com/greedy/festa/artist/entity/Lineup.java`
- **변경 내용**: `Lineup → Festival`은 필수 단방향 `ManyToOne LAZY`, `Lineup → Artist`는 nullable.
  `UNIQUE(festival_id, day, display_order)` 부여. `BaseEntity` 미상속, cascade·역방향 컬렉션 없음
- **이유**: `artist_id`가 null인 행이 시크릿 게스트다. Artist 행을 만들지 않고 표현할 수 있다.
  실제 출연일은 `festival.startDate + (day - 1)`로 계산하며 `performanceDate`를 저장하지 않는다 — 축제 시작일이나 `day`가 바뀌면 파생값이 어긋나기 때문 (DEC-0074)

#### 임포트 배치 엔티티

- **파일**: `src/main/java/com/greedy/festa/importer/entity/ImportBatch.java`, `ImportBatchType.java`, `ImportConflictPolicy.java`
- **변경 내용**: `fileNames`는 `@JdbcTypeCode(SqlTypes.ARRAY) List<String>`, `preview`는 텍스트 한 칼럼.
  `uploadedByAdmin`은 nullable FK. 생성자에서 `uploadedAt`을 강제하고 `expiresAt`을 `uploadedAt + 30분`으로 파생
- **이유**: 미리보기를 별도 저장소 없이 DB 한 행에 두고 30분 뒤 비우는 방식이다 (DEC-0055, DEC-0076)

#### 임포트 감사 엔티티

- **파일**: `src/main/java/com/greedy/festa/importer/entity/ImportCommitRow.java`, `ImportCommitPayload.java`, `ImportCommitAction.java`, `ImportCommitSection.java`
- **변경 내용**: 원본 CSV 행 단위로 `section` · `line` · `importKey` · `action`과 원본 `payload`를 `jsonb`로 보존.
  `ImportCommitPayload`는 `record`이며 CSV 컬럼명을 `@JsonProperty`로 매핑
- **이유**: `SKIP`을 포함해 임포트가 각 행을 어떻게 처리했는지 영구 보존한다 (DEC-0077)

#### 관리자 엔티티

- **파일**: `src/main/java/com/greedy/festa/admin/entity/AdminUser.java`
- **변경 내용**: `username`(유일) · `passwordHash` · `createdAt`. `BaseEntity` 미상속, `@CreatedDate`만 사용
- **이유**: `import_batch.uploaded_by_admin_id`가 참조할 대상이 필요하다. 아래 ADR 참고

#### Flyway 마이그레이션

- **파일**: `src/main/resources/db/migration/V20260819_1157__artist_lineup_import.sql`
- **변경 내용**: 위 6개 테이블 생성. FK 7개, 유니크 제약 4개
- **이유**: `ddl-auto: validate` 설정이므로 마이그레이션 없이 머지하면 `develop`이 기동에 실패한다. 리뷰 지적 사항

### 🧭 결정 기록 (ADR)

#### `admin_user` 스키마를 이 이슈에서 함께 만든다

- **문제**: `admin_user`는 관리자 인증(#27)의 테이블인데, `import_batch.uploaded_by_admin_id`가 이것을 FK로 참조한다. 이 이슈만 머지하면 참조 대상이 없어 마이그레이션이 실패한다
- **선택**: `AdminUser` 엔티티와 `admin_user` 테이블을 이 이슈에 포함
- **대안**:
  - `uploaded_by_admin_id`를 FK 없는 단순 `bigint`으로 — 참조 무결성을 잃고, 나중에 FK를 거는 마이그레이션이 또 필요하다
  - `import_batch`를 #27 이후로 미룸 — 임포트 도메인 전체가 인증에 묶인다
- **트레이드오프**: #27의 작업 브랜치가 이 브랜치 위에 스택된다. 이 이슈가 먼저 머지되어야 #27이 `develop`으로 갈 수 있다
- ⭐ **볼트 승격 권장** — 다른 이슈의 머지 순서를 강제하는 결정이다. `/capture`로 `knowledge/decisions/`에 등록

#### `uploadedAt`을 생성자에서 강제하고 `expiresAt`을 파생으로 둔다

- **문제**: 빌더가 `uploadedAt`을 강제하지 않아 null로 객체를 만들 수 있었고, `expiresAt` 계산에서 NPE가 났다. `@Column(nullable = false)`는 flush 시점에야 걸린다
- **선택**: 생성자에서 `Objects.requireNonNull(uploadedAt, "uploadedAt")`으로 막고, `expiresAt`은 빌더에서 받지 않고 `uploadedAt + 30분`으로 계산
- **대안**:
  - `@Column(nullable = false)`만 믿음 — 실패 지점이 객체 생성에서 flush로 밀려 원인 추적이 어렵다
  - `expiresAt`을 빌더 파라미터로 받음 — 호출자마다 30분을 다시 계산해야 하고 어긋날 여지가 생긴다
- **트레이드오프**: 만료 시각을 30분과 다르게 두려면 엔티티를 고쳐야 한다. 현재 그런 요구는 없다

#### 열거값을 문자열로 저장하고 DB에 CHECK를 걸지 않는다

- **문제**: 5종 열거값(`ArtistGenre` · `ImportBatchType` · `ImportConflictPolicy` · `ImportCommitAction` · `ImportCommitSection`)을 어떻게 보관할지
- **선택**: `@Enumerated(EnumType.STRING)` + DB는 `varchar`, CHECK 제약 없음
- **대안**:
  - ordinal 저장 — 상수 순서가 바뀌면 기존 행의 의미가 조용히 달라진다
  - CHECK 제약 — 어휘를 넓힐 때마다 마이그레이션이 필요하다 (DEC-0057)
- **트레이드오프**: DB가 어휘 밖 값을 막지 않는다. 현재는 애플리케이션 밖에서 값을 넣을 경로가 없다

### 🔧 주요 변경사항 상세

#### V20260819_1157__artist_lineup_import.sql

테이블 6개를 아티스트 → 관리자·임포트 순으로 생성. 식별자는 전부 `bigint GENERATED ALWAYS AS IDENTITY`,
시각 컬럼은 `timestamptz`.

FK 삭제 정책이 갈린다.

- `artist_alias → artist`, `lineup → festival|artist`, `import_commit_row → import_batch` — 기본값(`NO ACTION`)
- `import_batch → admin_user`, `import_commit_row → festival|artist` — `ON DELETE SET NULL`

감사 행은 참조 대상이 지워져도 남아야 하므로 후자다. 반대로 출연 이력이 남은 아티스트는 삭제를 막아야 하므로 전자다.

**특이사항**:

- `import_batch.file_names`는 `text[]`, `import_commit_row.payload`는 `jsonb`
- `lineup`의 유니크 제약 이름을 엔티티의 `@Table(uniqueConstraints = @UniqueConstraint(name = ...))`과 문자열까지 일치시켰다

#### ImportBatchTest

`uploadedAt`에 null을 넣은 빌더 호출이 `NullPointerException`을 던지고 메시지가 `"uploadedAt"`인지 확인한다.
엔티티 단위 테스트라 컨텍스트를 띄우지 않는다.

### 📦 의존성 변경

없음. 기존 `spring-boot-starter-data-jpa` · `flyway-core` · `flyway-database-postgresql`만 사용한다.

### 🧪 테스트 및 검증

**자동 검증** — `./gradlew build` 통과. 다만 이 빌드는 스키마 정합을 검증하지 않는다. 아래 「참고사항」 참고.

**로컬 실측** — 빈 PostgreSQL 16에 실제로 기동해 마이그레이션과 스키마 검증을 확인했다.

```bash
docker run -d --name festa-validate-pg \
  -e POSTGRES_USER=festa -e POSTGRES_PASSWORD={PASSWORD} -e POSTGRES_DB=festa \
  -p 55432:5432 postgres:16

DB_URL=jdbc:postgresql://localhost:55432/festa \
DB_USERNAME=festa DB_PASSWORD={PASSWORD} \
GOOGLE_CLIENT_ID={CLIENT_ID} GOOGLE_CLIENT_SECRET={CLIENT_SECRET} \
JWT_SECRET={SECRET} AES_KEY={AES_KEY} \
./gradlew bootRun
```

- Hibernate `validate` 통과 — `SchemaManagementException` 없음. 로그 전체에 `WARN` · `ERROR` 0건

### 📌 참고사항

**CI가 스키마 정합을 검증하지 못한다.** `PROJECT-SPRING-CI`는 `./gradlew build`만 실행하고 DB 서비스 컨테이너가
없다. 테스트 3개는 전부 순수 단위 테스트이며 `@SpringBootTest` · `@DataJpaTest`가 없고 Testcontainers 의존성도
없다. 즉 **Flyway와 `ddl-auto: validate`는 CI에서 한 번도 실행되지 않는다.**

이번 건은 로컬 실측으로 덮었지만, 다음에 누가 엔티티에 필드를 추가하고 마이그레이션을 빠뜨리면 CI는 똑같이
통과시킨 뒤 `develop` 기동을 깨뜨린다. `develop`은 푸시마다 E2로 자동 배포된다.

→ Testcontainers 기반 컨텍스트 로드 테스트를 CI에 추가하는 것을 별도 이슈로 제안한다.

**후속 작업 순서.** 이 이슈가 머지되어야 #27(관리자 로그인)이 `develop`으로 갈 수 있다.
#26(`/api` 접두사 제거)을 #27보다 먼저 넣는 편이 낫다 — #27의 `SecurityConfig`가 `/admin/**`에만 인증을 걸어서,
주최 API가 `/api/admin/hosts`로 남아 있으면 인증이 켜져도 그 경로는 계속 열린다.
