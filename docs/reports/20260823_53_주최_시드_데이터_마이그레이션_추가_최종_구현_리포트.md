# 주최 시드 데이터 마이그레이션 추가 최종 구현 리포트

## 작업 개요

Issue #53과 PR #58을 통해 크롤링 대상 대학 29곳을 `host` 테이블에 선등록하는 Flyway 데이터
마이그레이션을 추가했다. 이 리포트는 PR 초안이 아니라 `develop`에 반영된 merge commit
`f7aa0d3115051eb4fba3166346c17bfb6b1e4480`의 실제 코드를 기준으로 작성했다.

- 관련 Issue: `#53` — 주최 시드 데이터 마이그레이션 추가
- 관련 PR: `#58` — 주최 시드 데이터 마이그레이션 추가
- 최종 PR head: `966bf23981c23347567f5c1134e27aff6c1d6e30`

- develop merge commit: `f7aa0d3115051eb4fba3166346c17bfb6b1e4480`

## 구현 범위

- 크롤링 대상 대학 29곳의 Host 데이터 추가
- `name`, `short_name`, `region`, `homepage_url`, `instagram_url` 초기값 구성
- `created_at`, `updated_at`을 `now()`로 명시
- `ON CONFLICT (name) DO NOTHING`을 통한 기존 Host 보존과 재실행 안전성 확보
- crawler 시드의 대학명·지역과 backend Host 시드의 정합성 확인
- 기존 Artist Repository·merge 테스트의 Host 이름 충돌 해소
- 스키마, Entity, API 변경 없음

## Host 시드 데이터 구성

시드는 서울 소재 대학 29곳으로 구성한다. 각 행에는 다음 값을 저장한다.

| 컬럼 | 값과 근거 |
| --- | --- |
| `name` | `universities-2026.csv`의 `university`를 문자 그대로 사용 |
| `short_name` | 최종 확정한 통용 약칭 |
| `region` | `universities-2026.csv`의 `region`을 문자 그대로 사용 |
| `homepage_url` | 조사한 대학 홈페이지 URL |
| `instagram_url` | 조사한 대학 공식 Instagram 계정 URL |
| `logo_url`, `banner_url` | 값과 호스팅 주체가 미정이므로 null 유지 |
| `created_at`, `updated_at` | 컬럼 기본값이 없으므로 `now()` 사용 |

홈페이지와 Instagram URL은 crawler 시드에 없는 값이다. Instagram은 총학생회·학과·입학처나 축제
계정이 아닌 학교 공식 계정을 사용하며, 축제 계정은 `festival.instagram_url`에서 별도로 관리한다.

## Flyway migration 내용

`V20260822_2300__host_seed.sql` 한 파일을 추가했다. 스키마를 변경하지 않고 기존 `host` 테이블에
초기 데이터만 넣는다. Host가 없으면 Import Preview가 `host.name` 정확 일치 조회에 실패해
`HOST_NOT_FOUND` blocker를 만들기 때문에, 이 migration은 신규 환경에서 축제 import를 실행하기 위한
출발 데이터를 제공한다.

Flyway가 migration을 한 번만 적용하는 것이 기본 동작이며, SQL 자체도 이름 충돌을 안전하게 처리한다.
적용 후 관리자가 Host 값을 변경하면 그 시점부터 DB가 원본이다. 적용 완료된 migration 파일을 최신 값에
맞춰 다시 고치지 않으며, 이후 변경은 별도 migration이나 관리자 기능으로 처리한다.

## 기존 Host 보존과 멱등성

SQL 끝에 `ON CONFLICT (name) DO NOTHING`을 사용한다. `host.name`에는 `uq_host_name` UNIQUE 제약이
있으므로 같은 이름의 Host가 이미 존재하면 해당 행을 덮어쓰거나 실패하지 않고 건너뛴다.

- 기존 Host의 `short_name`, 지역, URL, 수정 시각을 보존한다.
- 기존 데이터가 있는 develop·운영 환경에도 안전하게 적용할 수 있다.
- 동일 SQL을 재실행해도 같은 이름의 행이 추가되지 않는다.
- 충돌이 없는 Host만 새로 삽입되므로 부분적으로 데이터가 있는 환경도 처리한다.

PR 본문에 기록된 PostgreSQL 17 수동 검증에서는 migration 5개 순차 적용, Host 29행 생성, 동일 SQL
2회 실행 후 29행 유지, 한글 저장을 확인했다. 전체 CI에서는 PostgreSQL 16 Testcontainers를 사용하는
테스트가 Spring context와 Flyway migration을 실제 적용한 상태로 통과했다.

## short_name 최종 정책

Issue 초기 내용은 표기 규칙이 정해지지 않았다는 이유로 `short_name`을 비워 두는 방향이었다. 리뷰 과정에서
현재 시드 대상 29곳이 확정되어 있고 각 대학의 흔히 사용하는 명칭을 일관된 규칙으로 정할 수 있다고
재판단했다. 최종 결정은 이번 migration에서 29건의 `short_name`을 모두 함께 저장하는 것이다.

- 기본 규칙: `X대학교` → `X대`
- 여자대학교 규칙: `X여자대학교` → `X여대`
- 통용 명칭 예외: 한국외국어대학교 → `한국외대`
- 통용 명칭 예외: 서울과학기술대학교 → `서울과기대`
- `연대`, `고대`처럼 짧고 모호할 수 있는 약칭은 사용하지 않는다.
- `short_name`은 표시용이며 조회·import 매칭 키는 계속 `name`이다.

최종 SQL에는 빈 `short_name`이 없고 중복도 없다. Issue #53 본문은 2026-08-23에 이 최종 계약으로
수정됐으며, migration 상단 주석에는 표기 결정 `DEC-0098`과 예외 근거가 남아 있다. 초기 방향에서 최종
결정으로 바뀐 이력은 Issue와 PR review thread에 보존되어 있다.

## 제한사항 및 후속 작업

- crawler 시드에 대학이 추가될 때 backend Host migration도 함께 추가한다는 저장소 간 동기화 규칙은
  아직 없다.
- 2027 시즌 시드에서 Host가 늘어날 경우 별도 migration을 쌓을지 다른 동기화 방식을 사용할지 정해야
  한다.
- Host 로고·배너의 값과 호스팅 주체가 미정이므로 `logo_url`, `banner_url`은 비어 있다.
- 홈페이지·Instagram URL은 crawler 시드에 없는 수동 조사 값이므로 향후 변경이나 계정 이전 시 DB에서
  갱신해야 한다.
- `ON CONFLICT DO NOTHING`은 기존 Host를 보존하므로, 이미 존재하는 행의 누락 필드를 시드 값으로
  보충하지 않는다. 이는 기존 데이터 우선 정책에 따른 의도된 동작이다.
- crawler CSV와 backend migration의 이름·지역 정합성을 지속적으로 검사하는 자동화는 별도 후속 검토가
  필요하다. 현재 직접 대응하는 Issue 번호는 없다.
