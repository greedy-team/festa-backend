## k6 공개 API 부하 테스트 구조

- `scenario.js`와 `config.js`에 upcoming/recent/Festival 목록·상세/Artist 목록·상세/search/Host 상세의 8개 공개 API scenario를 분리했다.
- `run.ps1`이 실행 대상, stage, scenario, fixture, runner와 run metadata를 검증·기록하고 `k6-summary.json`을 생성한다.
- `smoke-compose.yaml`, seed, up/down 스크립트로 PostgreSQL 17과 backend의 독립 smoke stack을 구성한다. 배포 volume과 #154 fixture volume은 사용하지 않으며, 결과 원본과 smoke image는 Git에서 제외한다.
- production과 shared development host는 wrapper와 scenario 양쪽에서 차단한다.

## scenario/search corpus/summary/threshold 핵심 설계

- `mixed`는 공개 읽기 API만 사용하는 고정 100-slot cycle이다. upcoming 12%, recent 10%, Festival 목록 18%, Festival 상세 12%, Artist 목록 18%, Artist 상세 10%, search 20%로 구성한다.
- 검색 corpus는 20개 고정 항목을 검색 요청 순서로 순환한다. common 1글자 30%, common 2글자 30%, rare 15%, 공백 정규화 15%, 영문 10%와 API type tag를 함께 기록해 반복·무작위 편향을 줄인다.
- stage는 smoke(100 iterations)와 baseline/normal/stress/saturation(5/15/30/50 RPS 시작값)으로 제공한다. 측정 stage는 동일 profile로 2분 이상 warm-up 후 해당 결과를 비교에서 제외하며, 최대 TPS는 합의한 latency/error 조건을 3분 이상 유지한 최고 rate로 후속 측정에서 판단한다.
- summary는 endpoint별 request count/RPS, latency, HTTP error, check failure와 실패 threshold를 JSON으로 저장한다. endpoint aggregate는 k6의 endpoint submetric을 사용하고, search bucket/type leaf series는 중복 없이 합산한다. 여러 시계열에서 percentile을 정확히 재구성할 수 없으면 p50/p95/p99를 `null`로 표시한다.
- threshold는 최종 TPS 합격선이 아닌 안전·계약 guard로만 둔다: HTTP failure < 1%, checks > 99%, p99 < 10초.

## 최신 리뷰 반영 내용

- #184/#185의 API 수준 전후 비교는 같은 #154 규모 fixture, image, stage, runner, 네트워크 조건으로 `b43c872` BEFORE를 먼저 측정한 뒤 최신 develop AFTER를 측정하도록 절차를 정리했다.
- 각 측정 전에 warm-up을 분리하고, app/PostgreSQL CPU·memory, DB connection, 가능한 JVM/GC/Hikari 지표를 run directory에 함께 수집하도록 명시했다.
- tag가 겹치는 k6 시계열에서 aggregate와 child series를 함께 더해 이중 집계하지 않도록 leaf series 집계 회귀 테스트를 추가했다.
- production 부하 금지 경계는 유지했다. 운영 A1 부하 허용 여부와 중단 기준은 이 PR에서 우회하지 않는다.

## smoke/test 검증 결과

이번 문서 작업에서는 테스트를 재실행하지 않았다. PR #191에서 다음 검증이 완료됐다.

- pinned `grafana/k6:0.54.0` 컨테이너에서 `summary.test.js` 통과
- 독립 로컬 smoke stack(`127.0.0.1:18080`)에서 `mixed` 100/100 iterations, exit 0
- HTTP error 0, checks 100%, endpoint 요청 100건(search 20건), search check failure 0
- overall p50/p95/p99: 15.9/28.6/33.2ms, `k6-summary.json` 생성 확인
- smoke container, network, 전용 PostgreSQL volume cleanup 완료
- PR CI: 82 suites, 708 tests, 750 runs 성공

위 latency는 로컬 Docker smoke 검증값이며, 최종 API TPS 성능 결과는 아니다.
