### 📌 작업 개요

관리자 API 전체를 `/api` 아래로 옮기고, Swagger 주소를 `/docs` 아래로 분리했다.
`/api/admin/hosts` 형태가 되며, 접두사 없는 옛 경로는 남기지 않는다.

**이것은 이전 결정을 뒤집는 작업이다.** 이슈 #26이 `HostAdminController`에서 `/api`를 떼어냈고
작업완료로 닫혔다. 팀 논의로 방향이 바뀌어 그 반대로 되돌린 것이며,
근거 결정은 DEC-0099(DEC-0084를 대체)다.

### 🔍 문제 분석

`develop`의 컨트롤러 5개가 전부 접두사 없이 도메인부터 시작하고 있었다.
실수가 아니라 이전 결정을 그대로 따른 결과다.

**URL만 바뀌는 작업이 아니었다.** `SecurityConfig`의 매처가 반드시 같이 움직여야 했다.

```java
.requestMatchers(HttpMethod.POST, "/admin/auth/login").permitAll()
.requestMatchers("/admin/**").authenticated()
.anyRequest().permitAll()
```

컨트롤러만 `/api/admin/...`으로 옮기면 `/admin/**` 매처에 걸리지 않고 `anyRequest().permitAll()`로
떨어진다. **관리자 API 전부가 토큰 없이 열린다.** 이슈 #26이 막았던 것과 같은 구멍이고 방향만 반대다.
404가 아니라 200이 나오므로 실패가 조용하다.

  파일당 한 줄
- **이유**: 클래스 레벨만 고치면 그 아래 메서드 매핑이 전부 따라온다

이슈를 쓸 당시 엔드포인트는 13개였으나, 작업 중 #46(PR #55, 관리자 축제 검수·발행)이 먼저 머지되어

`/api` 아래로 따라왔다.** 최종적으로 16개 엔드포인트가 이동했다.

- **파일**: `global/config/SecurityConfig.java`
- **변경 내용**: `POST /admin/auth/login` → `POST /api/admin/auth/login`(permitAll),
  `/admin/**` → `/api/admin/**`(authenticated). 2줄
- **이유**: 이 작업에서 가장 위험한 자리다. 컨트롤러와 **같은 커밋**에 넣어 둘이 갈라질 수 없게 했다

#### Swagger 주소 분리

- **파일**: `src/main/resources/application.yml`, `global/config/SwaggerConfig.java`
- **변경 내용**: `springdoc.api-docs.path: /docs/v3/api-docs`,
  `springdoc.swagger-ui.path: /docs/swagger-ui.html`. `SwaggerConfig`의 description에 문자열로 박힌
  `/admin`을 `/api/admin`으로 수정
- **이유**: API와 문서를 다른 접두사에 두기로 했다. actuator는 건드리지 않는다

`springdoc.swagger-ui.path`는 **진입 경로만 바꾸는 프로퍼티로 읽히기 쉬운데 실제 동작이 다르다.**
지정한 경로의 상위 디렉터리가 UI 리소스 루트가 되어, `/docs/swagger-ui.html`로 두면
화면이 `/docs/swagger-ui/index.html`에서 뜬다. 문서만 읽어서는 나오지 않아
**테스트를 먼저 쓰고(4개 전부 실패) 설정을 맞추는 순서로 확인했다.**

`springdoc.webjars.prefix` 계열로 리소스 베이스를 옮기는 방법은 매핑이 어긋나는 알려진 이슈가 있어
(springdoc-openapi #3145 · #454 · #2599) 쓰지 않았다.

#### 경로를 하드코딩한 테스트 갱신

- **파일**: `admin/controller/AdminAuthControllerTest.java`,
  `festival/controller/FestivalAdminControllerTest.java`,
  `importer/controller/ImportAdminControllerTest.java`,
  `global/config/SecurityConfigTest.java`
- **변경 내용**: 절대 경로를 `/api/...`로 갱신하고, `SecurityConfigTest`에 옛 경로가 남아 있지 않은지
  확인하는 테스트를 추가했다
- **이유**: `HealthEndpointSecurityTest`는 actuator 경로를 쓰므로 바뀌지 않는다

### 🧭 결정 기록 (ADR)

#### `server.servlet.context-path`를 쓰지 않음

- **문제**: `context-path: /api` 한 줄이면 컨트롤러를 한 줄도 안 고치고 끝난다.
  Spring Security가 서블릿 컨텍스트를 뗀 뒤 매칭하므로 **인증 매처 구멍이 아예 생기지 않는다**
- **선택**: 쓰지 않는다. 컨트롤러와 매처를 직접 옮긴다
- **대안**: context-path 사용 — Swagger와 actuator까지 예외 없이 `/api` 아래로 끌려간다.
  `/api/actuator/health`가 되면 배포 헬스체크 설정을 함께 고쳐야 한다
- **트레이드오프**: **주소 모양을 얻는 대가로 그 안전장치를 포기한 거래다.**
  이 작업의 최대 위험(매처 이동 누락 → 관리자 API 무방비)이 그대로 살아 있고,
  그래서 매처 변경을 컨트롤러와 같은 커밋에 묶고 `SecurityConfigTest`로 잠갔다
- ⭐ **볼트 승격 권장** — DEC-0099에 반영 완료

#### 접두사를 `addPathPrefix`가 아니라 컨트롤러 문자열로 붙임

- **문제**: `WebMvcConfigurer.configurePathMatch`의 `addPathPrefix`로 한 곳에서 붙이면
  새 컨트롤러가 자동으로 따라온다
- **선택**: 컨트롤러 5개에 문자열로 직접 적는다
- **대안**: `addPathPrefix` — 새 컨트롤러가 빠뜨릴 일이 없지만,
  **springdoc이 그 접두사를 생성 문서에 반영하는지 별도 실측이 필요하다.**
  반영하지 않으면 문서에 `/admin/hosts`로 나오는데 실제는 `/api/admin/hosts`여서
  Swagger UI의 Try it out이 404를 낸다. 컨트롤러 파일만 봐서 실제 URL을 알 수 없다는 문제도 있다
- **트레이드오프**: 같은 문자열이 5곳에 반복되고 새 컨트롤러가 빠뜨리기 쉽다.
  직접 매핑은 생성 문서가 실제 경로와 자동으로 일치한다는 것이 결정적이었다

#### 옛 경로를 남기지 않음

- **문제**: 두 경로를 다 받으면 프론트가 바뀌는 동안 무중단으로 넘어갈 수 있다
- **선택**: 접두사 없는 경로는 받지 않는다
- **대안**: 양쪽 수용 — 같은 자원에 경로가 둘이 되어 계약이 흐려지고,
  **인증 매처 두 벌 중 하나를 빠뜨리면 무방비 구간이 생긴다.**
  DEC-0084가 반대 방향에서 이미 탈락시킨 안이고, 그 이유는 방향과 무관하게 유효하다
- **트레이드오프**: 프론트가 같이 나가지 않으면 그 사이 호출이 전부 실패한다

#### 스웨거 테스트 두 클래스를 삭제 (범위 밖 판정)

- **문제**: 이 작업으로 `SwaggerPathTest` 4개를 새로 썼고, #49가 남긴
  `SwaggerDisabledByDefaultTest` 2개도 경로를 따라 옮겨야 했다
- **선택**: 둘 다 삭제했다. `SwaggerPathTest`는 dev 서버에만 띄우는 것이라 테스트로 지킬 값이 낮다는 판단이고,
  `SwaggerDisabledByDefaultTest`도 함께 걷어냈다
- **대안**: `SwaggerDisabledByDefaultTest`만 남기기 — 이쪽은 dev 전용이 아니라
  「운영에 관리자 API 명세가 새지 않는다」를 지키는 것이라 성격이 다르다는 의견이 있었다
- **트레이드오프**: **이제 운영 비노출을 지키는 것은 `application.yml`의 `enabled: false` 두 줄뿐이다.**
  공통 설정에 `true`가 잘못 들어가면 아무 에러 없이 열린다. 아래 참고사항 참조
- 이 삭제는 #49 산출물이라 경로 규칙과 근거가 다르다. **커밋을 따로 갈라** 리뷰어가 분리해 볼 수 있게 했다

`/api/admin/**`가 토큰 없이는 401인지, 유효 토큰과 만료 토큰이 구분되는지,
그리고 옛 경로가 남지 않았는지.

옛 경로 테스트는 **상태 코드로 못박지 않았다.**

```java
assertThat(응답.getStatus()).isNotEqualTo(HttpStatus.OK.value());
assertThat(응답.getContentAsString()).doesNotContain("ok");
```

이 테스트가 지키는 것은 "핸들러에 닿지 않는다" 하나다. 이유는 참고사항에 적었다.

### 📌 참고사항

**매핑 없는 경로는 404가 아니라 500이다.**
이슈 본문의 완료 조건에 "접두사 없는 옛 경로는 404다"라고 적었으나 실측하니 500이 나온다.
`GlobalExceptionHandler`의 `@ExceptionHandler(Exception.class)`가 핸들러 없음까지 전부 잡아
`INTERNAL_SERVER_ERROR`로 내보내기 때문이다. 옛 관리자 경로든 아무 오타 경로든 똑같다.

**이 작업이 만든 것이 아니라 매핑 없는 경로 전반의 기존 동작이다.**
고치려면 `NoHandlerFoundException` 핸들러를 붙이고 `CommonErrorCode.RESOURCE_NOT_FOUND`에
연결해야 하는데, 그 코드는 정의만 되어 있고 이를 내보낼 경로가 없다
(이슈 #17 리포트의 참고사항 참조). 경로 규칙과 다른 문제라 범위 밖으로 뒀다.

**운영에 API 명세가 새지 않는다는 것을 지키는 테스트가 없다.**
스웨거 테스트 두 클래스를 지운 결과다. 방어선은 `application.yml`의
`springdoc.api-docs.enabled: false` · `springdoc.swagger-ui.enabled: false` 두 줄이고,
development 프로파일에서만 켜진다. 공통 설정에 `true`가 들어가면
**아무 에러 없이 열리는 조용한 실패**다.

**프론트엔드가 같이 바뀌어야 한다 — 이 이슈 범위 밖이다.**
`festa-frontend`의 `src/lib/api.ts`는 `API_BASE`에 호스트까지만 담고 경로를 뒤에 붙인다.
`/api`를 `NEXT_PUBLIC_API_BASE_URL`에 넣을지 경로 조립부에 고정할지는 프론트에서 정해야 하고
별도 이슈가 필요하다. **백엔드만 먼저 나가면 그 사이 프론트 호출이 전부 실패한다.**
다만 이슈 #59(CORS 허용)가 열려 있어 프론트가 브라우저에서 개발 서버에 붙지 못하는 상태라
실사용 중인 호출은 없다.

**열린 PR과 겹치는 자리가 남아 있다.**

- **#59(CORS)** — `SecurityConfig.java`와 `application.yml` 두 파일이 겹친다.
  게다가 CORS 설정을 `/admin/**` 기준으로 썼다면 경로가 바뀐 뒤 맞지 않는다
- **#39(PR #40) · #41(PR #42)** — 통합 브랜치로 미리 합쳐 본 결과,
  두 PR이 새로 넣은 테스트가 옛 경로를 쓰고 있는데 **텍스트 충돌 없이 조용히 어긋난다.**
  `ImportAdminControllerTest` 4곳이다. git이 잡아주지 않으므로 머지할 때 손으로 확인해야 한다

- Swagger 어노테이션 보강은 넣지 않았다. 컨트롤러 5개 중 2개(`HostAdminController` ·
  `AdminAuthController`)에만 어노테이션이 있고 나머지 셋은 0개다 — #49가 그때 있던 컨트롤러만
  문서화했고 이후 들어온 것이 맨몸으로 남았다. 경로 규칙과 다른 문제이고 열린 PR과 크게 겹쳐서 미뤘다
