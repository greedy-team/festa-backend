# enum 쿼리 파라미터 파싱 통일 최종 구현 리포트

## 작업 개요

Issue #95와 PR #101을 통해 컨트롤러·서비스에 흩어진 enum 쿼리 파라미터 파싱을 공통 `EnumParser`와 각 enum의 `from(String)` 계약으로 통일했다. 기존에는 파라미터마다 대소문자·공백·기본값 처리가 달라 같은 API 안에서도 성공 여부가 갈렸고, 기본값과 도메인 에러 코드가 호출부에 중복돼 이후 다시 어긋날 수 있었다.

이 리포트는 PR 초안이 아니라 최신 `develop`의 merge commit `c0d9c3007a63641da91712f5821d9a3c7813fce0`에 반영된 코드, 최종 review thread와 GitHub Actions 결과를 기준으로 작성했다.

- 관련 Issue: #95
- 관련 PR: #101
- 최종 PR head: `02b06ba4c035d7f2287750d562071e25393b31e0`
- develop merge commit: `c0d9c3007a63641da91712f5821d9a3c7813fce0`

## 구현 범위

- `global/util/EnumParser` 추가
- 외부 문자열을 받는 enum 10종에 `from(String)` 계약 통일
- 컨트롤러·서비스의 중복 private 파싱 메서드 제거
- enum별 기본값과 도메인 에러 코드를 해당 enum의 `from` 한 곳으로 이동
- 대소문자와 앞뒤 공백을 무시하고 빈 값을 미지정과 같이 처리
- 공개 아티스트 목록 `sort`의 중복 기본값 제거
- Swagger에 enum 쿼리 파라미터 입력 규칙 명시
- 공통 파서, 컨트롤러와 서비스 회귀 테스트 보강

실패 계약이 다른 임포트 미리보기·커밋 내부 파싱과 `ImportSection.fromPath`는 변경하지 않았다.

## 최종 파싱 구조

`EnumParser.parse`가 모든 enum에 공통인 기계적 규칙을 담당한다.

1. 입력이 `null` 또는 blank이면 호출 enum이 지정한 기본값을 반환한다.
2. 값이 있으면 앞뒤 공백을 제거하고 `Locale.ROOT`로 대문자화한 뒤 `Enum.valueOf`로 변환한다.
3. 허용 어휘가 아니면 호출 enum이 지정한 도메인 `ErrorCode`로 `FestaException`을 던진다.

각 enum은 `from(String)`에서 자신의 기본값과 에러 코드를 소유한다. Controller와 Service는 `EnumParser`를 직접 참조하지 않고 `ArtistGenre.from(genre)`처럼 도메인 계약만 호출한다.

| enum | 기본값 | 오류 코드 |
| --- | --- | --- |
| `ArtistGenre` | `null` | `ARTIST_INVALID_GENRE_TYPE` |
| `ArtistSortType` | `CREATED_DESC` | `ARTIST_INVALID_SORT_TYPE` |
| `ArtistPublicSortType` | `APPEARANCES` | `ARTIST_INVALID_SORT_TYPE` |
| `FestivalCoverageStatus` | `null` | `FESTIVAL_COVERAGE_INVALID_STATUS` |
| `FestivalListSortType` | `LATEST` | `FESTIVAL_INVALID_SORT_TYPE` |
| `FestivalSortType` | `IMPORTED_DESC` | `FESTIVAL_INVALID_SORT_TYPE` |
| `FestivalStatus` | `null` | `FESTIVAL_INVALID_STATUS_TYPE` |
| `ImportConflictPolicy` | `UPDATE` | `IMPORT_INVALID_CONFLICT_POLICY` |
| `ImportBatchType` | `null` | `IMPORT_INVALID_TYPE` |
| `ImportBatchStatus` | `null` | `IMPORT_INVALID_STATUS` |

기존 정상 값, 기본값과 오류 코드는 유지했다. 의도한 외부 동작 변경은 완화 방향의 두 가지다.

- `?genre=hiphop`, `?sort=latest`, `?onConflict=update`처럼 소문자 또는 공백 패딩이 있는 값도 정식 enum 값과 동일하게 처리한다.
- 커버리지 `?status=` 빈 값은 400이 아니라 필터 미지정으로 처리한다.

## 리뷰 논의 및 반영 내용

### 기본값과 에러 코드의 소유 위치

- 논의: 최초 구현은 호출부가 `EnumParser.parse(...)`를 직접 호출했다. 공통 파싱 코드는 한 곳에 모였지만 `ArtistGenre`처럼 호출부가 둘인 경우 기본값과 에러 코드가 다시 중복됐다.
- 반영: commit `2a842f197e1a05e676613852a79182eb62b013a6`에서 외부 입력을 받는 enum 10종이 각자 `from(String)`을 갖도록 변경했다. 호출부 개수에 따라 helper 유무가 달라지는 예외 규칙도 제거했다.
- 결과: 공통 알고리즘은 `EnumParser`, enum별 계약은 각 `from`, 실제 호출은 `X.from()`으로 역할이 분리됐다.

### 공개 아티스트 정렬 기본값 중복

- 확인: `APPEARANCES` 기본값이 `ArtistController`의 `@RequestParam(defaultValue)`와 `ArtistPublicSortType.from` 양쪽에 있어 enum 쪽 기본값을 바꿔도 HTTP 요청에는 반영되지 않는 구조였다.
- 반영: commit `7227cb2a982b67618402f57e1ff7ee559be652b0`에서 Controller를 `required = false`로 바꾸고 기본값을 enum 한 곳에만 남겼다.
- 검증: 파라미터 생략과 빈 값의 기존 결과는 유지하고 Controller 테스트의 서비스 전달값을 `null`로 고정했다.

### Swagger 입력 계약

- 지적: 대소문자와 앞뒤 공백을 허용하는 새 입력 계약이 Swagger에 드러나지 않았다.
- 반영: commit `ad444f910bd1572497f9e088cf9ad4425d1f98a9`에서 Swagger 공통 API 설명에 정식 값은 대문자이며 입력 대소문자·앞뒤 공백을 무시하고 빈 값은 미지정과 같이 처리한다고 명시했다.
- 예외: 쿼리 파라미터와 규칙이 다른 단건 미리보기 경로 변수 `type`에는 별도 설명을 남겼다.

### `nameOrNull`의 위치

- 논의: `FestivalStatus.nameOrNull`을 공통화하며 `EnumParser`로 옮겼으나 이는 enum 파싱이 아니라 반대 방향의 문자열 변환이고 호출부도 한 곳뿐이었다.
- 반영: commit `02b06ba4c035d7f2287750d562071e25393b31e0`에서 원래 `FestivalStatus` 위치로 되돌렸다.
- 결과: `EnumParser`는 `parse` 책임만 가진다.

리뷰에서 제기된 항목은 모두 최종 코드와 문서에 반영됐으며 의도적으로 미반영한 finding은 없다.

## 제한사항 및 범위 밖

- `ImportPreviewService.enumValue`는 한 행의 오류를 `INVALID_ENUM` 문제 목록에 모으고 다음 행 검증을 계속해야 하므로 예외를 던지는 공통 파서를 사용하지 않는다.
- `ImportCommitService.enumValue`는 검증 완료 payload 복원 경로라 실패 의미가 사용자 입력 400이 아니라 내부 불변식 위반이다.
- `ImportSection.fromPath`는 예외 대신 `null`을 반환하는 별도 계약으로 이번 범위에서 유지했다.
- 기존 에러 코드 이름과 메시지, DB 스키마, 프론트엔드 코드는 변경하지 않았다.
- 검색어 `q`의 LIKE 이스케이프와 길이 상한은 Issue #98 범위다.
