## 제목

🔧 [설정][CORS] 프론트엔드 로컬 개발용 CORS 허용 설정 추가

## 본문

## 📝 작업 내용

- 백엔드에 CORS 허용 설정을 추가한다. 현재 애플리케이션 코드 전체에 CORS 관련 설정이 하나도 없다
- 허용 오리진은 프론트엔드 로컬 개발 서버로 한정한다. 지금 붙일 수 있는 조합이 그것 하나뿐이다
- 관리자 API의 프리플라이트 요청이 인증 없이 통과하게 한다. 지금은 프리플라이트가 관리자 경로의 인증 요구에 먼저 걸려 401로 떨어진다
- 허용 오리진을 환경별로 바꿀 수 있게 한다. 개발 서버와 운영이 같은 목록을 쓰지 않도록 한다
- 완료 조건
  - 프론트 로컬 개발 서버 오리진으로 프리플라이트를 보내면 2xx로 응답하고 Access-Control-Allow-Origin 헤더가 함께 온다
  - 허용 목록에 없는 오리진에는 그 헤더가 붙지 않는다
  - 토큰 없이 관리자 API를 부르면 지금처럼 401 UNAUTHORIZED가 그대로 유지된다. CORS 허용이 인증을 무르게 하지 않는다

## 🎯 필요한 이유

- 프론트엔드가 관리자 페이지를 백엔드 개발 서버에 붙이려 하는데, 브라우저에서 직접 호출하는 경로가 전부 막혀 있다
- 개발 서버에 직접 확인한 결과다. 프론트 오리진을 붙여 프리플라이트를 보내면 401이 돌아오고 Access-Control-Allow-Origin 헤더가 없다. 브라우저는 프리플라이트가 실패하면 본 요청을 보내지 않으므로, 화면에서는 모든 관리자 API 호출이 실패한다
- 서버와 배포된 API 자체는 정상이다. 헬스 체크는 UP이고 관리자 엔드포인트 13개가 모두 올라가 있으며, 토큰 없이 부르면 계약대로 401 UNAUTHORIZED가 온다. 남은 것은 브라우저에서 부를 수 있게 하는 설정 하나다
- 관리자 화면은 크롤러 산출물 검수와 임포트가 들어가는 자리라, 여기가 막혀 있으면 프론트가 관리자 작업을 하나도 시작하지 못한다

## ⚠️ 영향 범위

- 개발 환경. 프론트엔드가 로컬에서 백엔드 개발 서버에 붙을 수 있게 된다
- 인증 정책은 바꾸지 않는다. 관리자 경로는 계속 토큰을 요구한다
- 배포된 Vercel 프론트에서는 이 작업만으로 붙지 않는다. 개발 서버가 HTTP이고 Vercel이 HTTPS라 브라우저가 mixed content로 차단한다. 서버에 HTTPS를 붙이거나 프론트에서 서버 사이드로 우회하는 별도 판단이 필요하며, 이 이슈 범위가 아니다
- 프론트 로컬 개발 서버 포트가 기본값이 아닌 경우 허용 목록 조정이 필요하다
