## 본문

## 📝 배경

크롤링은 초안 생성기이고 최종 신뢰는 사람이 담보한다. 데이터 파이프라인 설계는 처음부터 수집 경로를 둘로 두고, 그 역할 분담을 전체의 축으로 삼았다.

```
[크롤링 수집] ─┐
               ├─→ [통합 정규화] → [검수 큐] → [발행]
[수동 입력]  ─┘
```

| 경로 | 강점 | 약점 | 역할 |
| --- | --- | --- | --- |
| 크롤링 | 커버리지, 속도 | 정확도 보증 불가 | 초안 대량 생산 |
| 수동 입력 | 정확도 | 인력 소요 | **최종 확정, 크롤링 실패 보완** |

**두 번째 경로가 축제·라인업에 대해서만 비어 있다.**

### 현재 상태

| 도메인 | 등록 | 수정 | 삭제 | 관리자 화면 |
| --- | :---: | :---: | :---: | --- |
| Artist | ✅ | ✅ | ✅ | ❌ 없음 |
| Host | ✅ | ✅ | ✅ | ❌ 없음 |
| **Festival** | ❌ | ❌ | ❌ | 검수 목록·발행만 |
| **Lineup** | ❌ | ❌ | ❌ | ❌ 없음 |

구멍이 두 방향이다.

- **Festival·Lineup은 API가 없다.** 축제는 목록·`coverage`·발행/일괄발행/발행해제뿐이고, 라인업은 Entity·Repository만 있고 Controller가 없다. 아티스트·주최는 임포트 없이도 손으로 만들 수 있는데, **정작 크롤러가 채우는 축제·라인업이 임포트가 유일한 입구다.**
- **Artist·Host는 반대다.** API는 8월에 전부 들어갔는데 그것을 쓰는 화면이 없다. 관리자 콘솔에서 지금 할 수 있는 일은 축제 목록 보기와 발행/해제가 전부다.

### 스키마는 이미 이 기능을 전제하고 있다

`V20260814_1658__festival.sql`의 주석이다.

> `import_key`는 UNIQUE지만 nullable — **어드민 직접 등록은 값이 없고**, Postgres는 NULL을 서로 다른 값으로 보므로 여러 행이 NULL이어도 UNIQUE가 안 깨진다.
>
> NOT NULL이 셋뿐인 것은 의도다. **미완성 저장을 허용하고 발행 게이트가 막는다.**

즉 `name`·`startDate`·`endDate`만 있으면 저장되고, 나머지는 발행 게이트가 책임진다는 설계가 스키마에 이미 들어가 있다.

### 결정은 있는데 작업 항목이 된 적이 없다

2026-08-09 회의에서 「축제 등록·수정·삭제, 축제 검수, 분실물 CRUD, 대시보드」를 만들기로 했다. 축제 검수(#46)와 대시보드(#53)는 만들어졌고, **축제 등록·수정·삭제는 이슈 전수 검색에서 0건이다.**

### 막고 있는 실제 데이터

`festa-crawler` 산출물(`output/2026`, 29개 대학)을 임포트 검증 규칙으로 전수 대조한 결과다. **아래는 크롤링을 아무리 고쳐도 안 나오는 것들이며, 전부 지금 어드민에서 고칠 수 없다.**

| 대학 | 빠진 값 | 원인 | 임포트 결과 |
| --- | --- | --- | --- |
| 건국대학교 | 축제명 | 원문이 "2026 건국대학교 대학 축제"라고만 부른다 | 축제 `INVALID` → **생성 안 됨** |
| 서울대학교 | 라인업 12행 중 10행의 `day` | 원문이 "1부 공연 라인업"으로 나누고 일차를 밝히지 않는다 | **라인업 10행 유실** |
| 서울시립대학교 | 라인업 6행 전부의 `day` | 6명이 한 문장에 나열되고 일차 구분이 없다 | 유효 라인업 0 → **`LINEUP_EMPTY`로 발행 불가** |
| 고려대학교 | 라인업 전체 | 입실렌티는 라인업을 사전 공개하지 않는 것이 전통 | 라인업 0 → **`LINEUP_EMPTY`** |
| 성신여대 · 숙명여대<br>동덕여대 · 삼육대 | 축제 전체 | 2026년 소스가 존재하지 않는다 (후보 URL 전수 확인) | `SKIP` 또는 라인업 0 |

운영자는 임포트 미리보기에서 이 행들을 **볼 수는 있으나 고칠 수단이 없고**, 커밋해도 그 행은 들어가지 않는다.

## 🎯 목표

- 크롤러가 채우지 못한 축제·라인업 값을 **관리자가 직접 등록·수정·삭제**할 수 있게 한다.
- 이미 있는 Artist·Host API에 **화면을 붙여** 관리자 콘솔에서 실제로 쓸 수 있게 한다.
- 임포트 경로의 계약(검증·감사·발행 게이트)은 **그대로 두고**, 수동 입력을 별도 경로로 나란히 놓는다.

## 🌐 API 개요

모두 `/api/admin/**` 아래이며 인증만 요구한다(권한 구분 없음). 에러 응답은 공통 4필드 형식을 따른다.

### 축제

| Method | Endpoint | 성공 | 설명 |
| --- | --- | :---: | --- |
| `POST` | `/api/admin/festivals` | 201 | 신규 등록. 필수는 `name`·`startDate`·`endDate` 셋 |
| `PATCH` | `/api/admin/festivals/{id}` | 200 | 부분 수정 |
| `DELETE` | `/api/admin/festivals/{id}` | 204 | 삭제 |

### 라인업

| Method | Endpoint | 성공 | 설명 |
| --- | --- | :---: | --- |
| `POST` | `/api/admin/festivals/{festivalId}/lineup` | 201 | 행 추가 |
| `PATCH` | `/api/admin/festivals/{festivalId}/lineup/{lineupId}` | 200 | 행 수정 |
| `DELETE` | `/api/admin/festivals/{festivalId}/lineup/{lineupId}` | 204 | 행 삭제 |

라인업은 축제에 종속되므로 축제 하위 경로에 둔다. `artistId`가 `null`인 행은 시크릿 게스트이며, 그 자리 자체가 정보이므로 등록을 허용한다.

### 에러 코드

기존 `FESTIVAL_NOT_FOUND` · `HOST_NOT_FOUND` · `ARTIST_NOT_FOUND` · `INVALID_DATE_RANGE`를 재사용하고, 라인업 쪽에 필요한 코드를 새로 정의한다. 이름 규약은 `{DOMAIN}_{사유}`를 따른다.

## 🖥️ 화면 범위

| 화면 | 상태 | 선행 조건 |
| --- | --- | --- |
| 아티스트 관리 (목록·등록·수정·삭제·병합) | 신규 | **없음 — API가 이미 있어 바로 착수 가능** |
| 주최 관리 (목록·등록·수정·삭제) | 신규 | **없음 — API가 이미 있어 바로 착수 가능** |
| 축제 등록·수정 폼 | 신규 | 이 문서의 축제 API |
| 라인업 편집 (행 추가·수정·삭제) | 신규 | 이 문서의 라인업 API |

기존 축제 검수 화면에서 각 행의 **"고치기"**로 축제 등록·수정 폼에 진입하는 동선을 둔다. 임포트 미리보기에서 `INVALID`를 확인한 운영자가 곧바로 손으로 채우는 경로가 이것이다.

## 🧭 착수 전 확인

- **어드민이 만든 축제에 `import_key`를 줄 것인가.** 스키마는 비워두는 것을 전제하지만, 비우면 나중에 크롤러가 같은 축제를 임포트할 때 매칭 키가 없어 **축제가 둘이 된다.** 임포트가 기존 행을 찾는 유일한 키가 `import_key`다.
- **발행된 축제의 수정을 허용할 것인가.** 임포트는 `FESTIVAL_ALREADY_PUBLISHED`로 막는데, 어드민 직접 수정까지 막으면 발행 후 오타를 못 고친다.
- **`day`가 축제 기간을 벗어나면.** 임포트에는 `LINEUP_DAY_OUT_OF_RANGE` 검증이 있다. 어드민 입력에도 같은 규칙을 걸지 정한다.
- **좌표를 어드민에서 고칠 수 있게 할 것인가.** 좌표의 원본은 크롤러 시드로 정해져 있어, 어드민에서 고치면 다음 임포트가 되돌린다.
- **라인업 에러 코드의 접두어.** 현재 도메인 접두어는 `FESTIVAL_`·`ARTIST_`·`HOST_`·`IMPORT_`뿐이다. `LINEUP_`을 새로 열지, 축제 하위 자원이므로 `FESTIVAL_`을 쓸지 정한다.

## 🚫 제외 범위

- 되돌리기·변경 이력 — `import_commit_row` 감사 행은 임포트 경로 전용이며 어드민 수정까지 넓히지 않는다
- 분실물 CRUD — 축제 기능 뒤로 미뤄져 있다
- 임포트 미리보기 행의 직접 편집 — 미리보기는 30분 만료 스냅샷이고, 교정은 커밋 이후 엔티티에 대해 한다
- 크롤러 쪽 수정 — 인코딩·프롬프트 개선은 `festa-crawler`에서 별건으로 다룬다
- 열거값 안전망 — #31

## ✅ 완료 조건

- `POST /api/admin/festivals`가 `name`·`startDate`·`endDate`만으로 축제를 생성하고 201을 반환한다.
- 좌표·주최·라인업이 없어도 저장되며, 발행 시 기존 게이트(`LINEUP_EMPTY`·`HOST_NOT_LINKED`·`COORDINATES_MISSING`)가 그대로 동작한다.
- `PATCH /api/admin/festivals/{id}`가 전달된 필드만 수정하고, 전달하지 않은 필드를 `null`로 덮지 않는다.
- 축제 수정 경로가 `Festival.updateFromImport(...)`를 호출하지 않는다.
- `DELETE /api/admin/festivals/{id}`가 종속 Lineup을 함께 정리하고 204를 반환한다.
- 라인업 등록·수정이 `(festival_id, day, display_order)` 중복 시 전용 에러 코드로 409를 반환한다.
- `artistId`가 `null`인 라인업 행을 등록할 수 있다.
- 없는 축제·라인업에 대한 요청이 404를 반환한다.
- 인증 없는 요청이 인증 계층의 공통 401을 따른다.
- 관리자 콘솔에서 아티스트·주최·축제·라인업을 **화면만으로** 등록·수정·삭제할 수 있다.
- 위 「막고 있는 실제 데이터」 표의 7개 대학을 화면에서 전부 채울 수 있다.

## 🧪 테스트 항목

- 축제 등록 — 필수 셋만으로 성공 / 필수 누락 400 / `endDate < startDate` 400
- 축제 부분 수정 — 일부 필드만 전달 시 나머지 보존 / 없는 id 404 / 없는 `hostId` 404
- 축제 삭제 — 라인업이 있는 축제 삭제 후 잔여 행 0 / 없는 id 404
- 라인업 등록 — 정상 / 슬롯 중복 409 / `artistId` null 허용 / 없는 `artistId` 404
- 라인업 수정·삭제 — 정상 / 다른 축제의 `lineupId` 404
- 인증 — 토큰 없이 6개 엔드포인트 전부 401
- 통합 — `ddl-auto: validate`가 도는 환경에서 등록→수정→발행 흐름
- 회귀 — 임포트 커밋 경로의 기존 테스트가 그대로 통과한다
