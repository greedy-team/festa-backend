## 📝 작업 내용

- springdoc-openapi 의존성을 추가한다. 버전은 3.1.0을 쓴다 — 2.x 계열은 Spring Boot 3 전용이라 현재 쓰는 Boot 4.1.0에서 동작하지 않고, 3.1.0이 Boot 4.1.0을 대상으로 올라온 버전이다. Spring Boot BOM이 관리하지 않는 의존성이라 버전을 직접 적는다
- 실행 프로파일을 나눈다. 지금은 `application.yml` 하나뿐이라 환경별로 켜고 끌 수단이 없다. 문서 생성과 스웨거 화면은 공통 설정에서 꺼두고 개발 프로파일에서만 켠다. 프로파일을 지정하지 않으면 꺼진 상태가 기본이 되도록 한다
- develop 자동 배포 서버에서는 켠다. 배포 워크플로우가 이미 development / production 환경을 구분해 계산하고 있으므로 그 값을 실행 프로파일로 넘긴다. 운영(main) 배포는 끈 채로 둔다
- 문서 기본 정보를 설정한다 — 제목, 설명, 버전
- 관리자 API를 스웨거 화면에서 바로 시험할 수 있도록 JWT 인증 스킴을 등록한다. 지금은 로그인으로 토큰을 받아 매번 헤더에 붙여야 한다
- 공통 에러 응답 형식을 문서에 드러낸다. 에러 응답 네 필드는 이미 통일돼 있으나(#17) 어느 엔드포인트가 어떤 에러 코드를 던지는지는 코드를 열어야 알 수 있다. 엔드포인트별 에러 코드를 응답 설명에 적는다
- develop에 있는 컨트롤러에 문서용 설명을 붙인다. 착수 시점의 develop 기준이며, 현재는 관리자 로그인과 관리자 주최 등록·목록·수정·삭제 둘이다
- 시큐리티 설정은 건드리지 않는다. 현재 관리자 경로 외에는 전부 열려 있어 스웨거 경로가 이미 접근 가능하고, 프로파일로 꺼두면 경로 자체가 등록되지 않는다. 공개 여부를 통제하는 것은 프로파일 하나다
- 노션 API 명세를 동결한다. 앞으로 계약의 원본은 코드이며, 노션 문서 상단에 동결 안내와 이 이슈 링크를 남긴다
- README에 로컬 실행 시 프로파일 지정 방법과 스웨거 주소를 적는다

## 🎯 필요한 이유

- 명세와 구현이 갈린 자리가 이미 여러 곳이다. 관리자 API 경로에서 `/api` 접두사를 걷어냈고(#26), 아티스트 등록·수정에서 이미지 주소를 받지 않기로 했고(#32), 에러 코드 이름 두 개가 명세 표기와 다르다. 프론트가 실물이 무엇인지 확인할 방법이 지금은 없다
- 관리자 API는 인증이 필요해서 손으로 시험하려면 로그인, 토큰 복사, 헤더 첨부를 매번 반복해야 한다
- 노션 명세는 사람이 갱신해야 해서 구현이 바뀔 때마다 어긋난다. 문서를 코드에서 만들면 어긋날 자리가 사라진다
- 2026-08-09 회의에서 이미 전제였다 — 초기 형식만 손으로 정리하고 나머지는 스웨거로 간다는 이야기가 있었다

## ⚠️ 영향 범위

- 빌드: 의존성 한 개가 추가된다
- 개발 환경: 프로파일이 새로 생긴다. 로컬 실행 시 프로파일 지정이 필요해지므로 README를 함께 고친다
- 배포: 배포 워크플로우와 compose 설정에 실행 프로파일 전달이 추가된다. develop 서버는 스웨거가 켜지고 운영은 꺼진다
- 제품 코드: 컨트롤러와 응답 형식에 문서용 설명이 붙는다. 동작은 바뀌지 않는다
- 진행 중인 작업과 겹친다. #32, #36, #46이 같은 컨트롤러를 만지는 중이므로 문서용 설명은 develop에 이미 있는 것까지만 붙이고, 아티스트 API는 #32가 머지된 뒤에 따로 붙인다
- 노출 범위: develop 서버는 인터넷에 열려 있어 관리자 API 목록과 파라미터가 공개된다. 로그인 경로는 스웨거가 없어도 이미 공개돼 있고 인증 요구는 그대로이므로 이 단계에서는 감수한다. 실제 사용자가 붙기 전에 다시 판단한다
- 스웨거는 구현된 것만 비춘다. MVP 1차 엔드포인트 25개 중 지금 구현된 것은 둘이므로 동결한 노션 명세가 나머지 계약의 근거로 계속 남는다. 동결은 갱신 중단이며 폐기가 아니다
