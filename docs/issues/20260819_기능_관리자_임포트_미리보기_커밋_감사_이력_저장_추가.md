## 제목

✨ [기능요청][관리자][임포트] 미리보기 커밋 및 감사 이력 저장 추가

## 본문

### 🧩 배경

Issue #37에서는 `festa-crawler`가 생성한 CSV를 업로드하여 파싱·검증하고, DB 매칭 결과와 예상 반영 action을 포함한 미리보기를 생성한 뒤 `ImportBatch.preview`에 저장한다.

현재 저장용 preview는 원본 CSV를 다시 받지 않고도 후속 반영을 수행할 수 있도록 다음 정보를 보존한다.

- 최상위 `schemaVersion: 1`
- conflict policy
- section / line / importKey
- 예상 action과 skip 사유
- normalized input과 원본 CSV payload
- Host / Artist / Festival 매칭 정보
- Artist 매칭 상태
- blocker에 대응하는 row errors 및 warnings
- `revealed`, `imageUrls`, `ticketOpenAt` 원문

다만 현재는 preview 생성까지만 구현되어 실제 `Artist`, `ArtistAlias`, `Festival`, `FestivalHashtag`, `Lineup` 데이터는 변경되지 않으며, `ImportCommitRow` 감사 이력도 저장되지 않는다.

이번 이슈에서는 유효한 `ImportBatch.preview`를 역직렬화하여 관리자가 확정한 결과를 실제 DB에 반영하고, 반영된 각 CSV 행의 감사 이력을 저장한다.

### 🎯 목표

- `POST /admin/imports/{importId}/commit` API를 제공한다.
- 원본 CSV 재업로드 없이 `ImportBatch.preview` 저장 모델만으로 commit한다.
- `artists → festivals → lineups` 순서로 반영한다.
- 전체 과정을 하나의 트랜잭션으로 처리한다.
- 중간에 하나라도 실패하면 도메인 변경, 감사 이력, `committedAt` 갱신을 모두 rollback한다.
- commit 직전 현재 DB 상태를 재검증하여 preview 이후 변경으로 인한 잘못된 반영을 방지한다.
- commit한 각 CSV 행을 `ImportCommitRow`로 저장한다.

### 📋 API 개요

#### Endpoint

```http
POST /admin/imports/{importId}/commit
Authorization: Bearer {adminAccessToken}
Content-Type: application/json
```

| 항목 | 내용 |
| --- | --- |
| Path variable | `importId`: 기존 `ImportBatch.id` 타입인 `Long` |
| 인증 계약 | `/admin/**` 관리자 JWT 필요 |
| 실제 인증 기능 구현 | 이번 이슈 범위 밖 |

#### Request

```json
{
  "lines": {
    "festivals": [3, 5, 8],
    "lineups": [3, 4, 5, 6]
  }
}
```

- `lines`는 section별 preview line 선택 구조다.
- `line`은 header를 제외한 section별 데이터 행 기준 1부터 시작한다.
- `lines` 생략 시 전체 preview의 commit 가능한 행을 모두 선택한다.
- artists / festivals는 정상 row 단위 선택을 허용한다.
- lineups는 Festival 단위 원자성 규칙을 적용한다.
- 존재하지 않는 section 또는 line은 `IMPORT_INVALID_LINE_SELECTION`으로 처리한다.
- 선택하지 않은 row는 도메인 반영 및 `ImportCommitRow` 생성 대상이 아니다.

#### Commit 전 기본 검증

- `ImportBatch` 존재 여부
- 이미 commit된 batch인지
- `expiresAt` 기준 만료 여부
- preview 존재 여부
- preview JSON 역직렬화 가능 여부
- `schemaVersion` 지원 여부
- 요청한 section과 line이 실제 preview에 존재하는지
- preview 이후 변경된 현재 DB 상태에서도 기존 예상 action을 안전하게 수행할 수 있는지

#### 기존 확정 오류

| 상황 | ErrorCode | HTTP Status |
| --- | --- | --- |
| ImportBatch 없음 | `IMPORT_NOT_FOUND` | `404 Not Found` |
| 이미 commit됨 | `IMPORT_ALREADY_COMMITTED` | `409 Conflict` |
| preview 만료 | `IMPORT_EXPIRED` | `410 Gone` |
| 지원하지 않는 preview schemaVersion | `IMPORT_UNSUPPORTED_PREVIEW_VERSION` | `409 Conflict` |
| 손상되었거나 역직렬화할 수 없는 preview | `IMPORT_INVALID_PREVIEW` | `500 Internal Server Error` |
| 존재하지 않는 section/line 또는 Lineup 원자성 위반 | `IMPORT_INVALID_LINE_SELECTION` | `400 Bad Request` |
| 선택 row에 INVALID 또는 미해결 blocker 존재 | `IMPORT_UNCOMMITTABLE` | `409 Conflict` |
| preview 이후 DB 상태 변경으로 안전한 commit 불가 | `IMPORT_PREVIEW_STALE` | `409 Conflict` |

### 🔄 트랜잭션 및 처리 순서

commit Service의 단일 public 메서드에 `@Transactional`을 적용하고 한 트랜잭션 안에서 다음 순서로 처리한다.

1. ImportBatch 조회 및 중복 commit·만료 검증
2. 저장된 preview 역직렬화 및 `schemaVersion` 검증
3. 요청 section/line, Lineup Festival 단위 원자성, 선택 row 의존성 검증
4. commit 직전 DB 상태 일괄 재조회 및 재검증
5. Artist / ArtistAlias 반영
6. Festival / FestivalHashtag 반영
7. Lineup 반영
8. CREATE / UPDATE / SKIP 대상 `ImportCommitRow` 감사 이력 저장
9. `ImportBatch.committedAt` 갱신

어느 단계에서든 예외가 발생하면 모든 변경을 rollback한다.

### 🎤 Artist / ArtistAlias 반영

- preview의 `action`, `artistMatchStatus`, `matchedArtistId`, normalized payload를 사용한다.
- `MATCHED`는 commit 시 현재 Artist를 다시 확인한 뒤 UPDATE 또는 SKIP한다.
- `NEW`는 Artist를 생성하고 생성된 ID를 같은 commit의 Lineup 연결에 사용한다.
- 신규 Artist는 crawler 입력과 기존 계약에 따라 `needsReview` 상태를 보존한다.
- UPDATE 시 CSV의 빈 선택값은 기존 값을 삭제하지 않고 유지한다.
- alias는 기존 alias와 CSV alias의 합집합을 예상값으로 사용한다.
- 선택한 `UNRESOLVED` 행은 `IMPORT_UNCOMMITTABLE`로 거부한다.
- alias 합집합 적용 전에 현재 소유권을 다시 확인하고, 추가하려는 alias가 다른 Artist에 연결되어 있으면 임의 이동·병합하지 않고 전체 transaction을 거부한다.
- alias 소유권이 preview 이후 달라진 경우 `IMPORT_PREVIEW_STALE`로 처리한다.
- preview 당시 신규여서 `matchedArtistId = null`인 행은 canonical name/importKey 기반 commit 실행 맵으로 생성 ID를 연결한다.

### 🎪 Festival / FestivalHashtag 반영

- crawler가 전달한 `importKey`를 그대로 사용하며 백엔드에서 새로 생성하지 않는다.
- CREATE / UPDATE / SKIP 예상 action을 commit 직전 현재 DB 상태와 대조한다.
- Host를 자동 생성하지 않는다.
- preview의 `matchedHostId`를 사용하되 Host가 현재도 존재하며 입력 `host_name`과 유효하게 대응하는지 재검증한다.
- UPDATE 시 CSV의 빈 선택값은 기존 값을 삭제하지 않고 유지한다.
- preview에서 확정한 normalized `posterUrl` 후보를 사용한다.
- `imageUrls` 원본 배열은 감사 payload에 보존하되 별도 이미지 Entity/테이블을 추가하지 않는다.
- CREATE된 Festival은 미발행 상태로 저장하며 commit 시 `publishedAt`을 설정하지 않는다.
- 이미 발행된 Festival은 수정하지 않고 실제 action을 SKIP으로 전환하여 감사 기록한다.
- preview 이후 발행된 Festival을 대상으로 선택된 Lineup이 있으면 commit을 거부한다.
- FestivalHashtag CREATE 시 CSV hashtag를 그대로 생성하되 중복을 제거한다.
- FestivalHashtag UPDATE 시 CSV hashtag가 비어 있으면 기존 값을 유지하고, 값이 있으면 중복을 제거한 CSV 값으로 전체 교체한다.

### 🎸 Lineup 반영

- Artist와 Festival 반영 이후 실행한다.
- 같은 commit에서 생성된 Artist와 Festival의 ID를 연결한다.
- `revealed=false`인 행은 nullable Artist로 저장할 수 있다.
- `(festival_id, day, display_order)` unique 제약을 준수한다.
- 최신 명세의 Festival 단위 Lineup 전체 교체 원칙을 따른다.
- 전체 교체이므로 Lineup의 결과 집계에서 UPDATE는 발생하지 않고 `updated = 0`이다.
- 특정 Festival의 Lineup row를 하나라도 선택했다면 그 Festival에 속한 commit 가능한 Lineup preview row를 모두 선택해야 한다.
- 일부만 선택하면 `IMPORT_INVALID_LINE_SELECTION`으로 거부한다.
- 선택 Lineup이 같은 batch에서 CREATE 예정인 Festival 또는 Artist를 참조하면 해당 의존 row도 commit 대상으로 선택되어 있어야 한다.
- 의존 row가 선택되지 않았다면 `IMPORT_INVALID_LINE_SELECTION`으로 거부한다.
- 발행된 Festival의 Lineup은 변경하지 않으며, 해당 Lineup이 선택되어 있으면 데이터 일관성을 위해 commit을 거부한다.

### 🧾 ImportCommitRow 감사 이력

DEC-0077과 기존 Entity를 재사용하여 실제 commit 대상으로 처리된 각 CSV 행을 저장한다.

최소 저장 항목:

- `batch`
- `section`: `ARTISTS`, `FESTIVALS`, `LINEUPS`
- `line`
- `importKey`
- `action`: `CREATE`, `UPDATE`, `SKIP`
- `festival` FK(nullable)
- `artist` FK(nullable)
- 원본 CSV 행을 담은 `ImportCommitPayload` JSONB
- `committedAt`

감사 규칙:

- CREATE / UPDATE / SKIP 행을 모두 저장한다.
- SKIP도 감사 이력에서 누락하지 않는다.
- `ImportCommitAction`에는 INVALID가 없고 DEC-0077도 CREATE / UPDATE / SKIP만 정의하므로 INVALID 행은 `ImportCommitRow`로 저장하지 않는다.
- Festival 또는 Artist가 이후 삭제되어 FK가 null이 되더라도 `importKey`와 payload는 유지한다.
- payload는 CSV 원본 필드 구조와 snake_case 키를 유지하며 `ticket_open_at`은 원문 String으로 보존한다.
- `committedAt`은 Service에서 실제 commit 시각을 `Instant`로 공급한다.

### 📤 Commit Response

최종 응답 구조는 다음과 같다.

```json
{
  "importId": 37,
  "committedAt": "2026-08-19T06:50:00Z",
  "result": {
    "artists":   { "created": 0, "updated": 0, "skipped": 0, "failed": 0 },
    "festivals": { "created": 0, "updated": 0, "skipped": 0, "failed": 0 },
    "lineups":   { "created": 0, "updated": 0, "skipped": 0, "failed": 0 }
  },
  "createdFestivalIds": []
}
```

- `importId`는 `ImportBatch.id`와 동일한 `Long`이다.
- 별도 `imp_...` 공개 ID는 도입하지 않는다.
- API 계약 호환성을 위해 `failed`를 유지하며 단일 트랜잭션 성공 응답에서는 항상 0이다.
- Lineup 전체 교체 정책상 `lineups.updated`는 항상 0이다.
- `createdFestivalIds`에는 이번 commit에서 실제 CREATE된 Festival만 포함한다.
- UPDATE, SKIP, 선택되지 않은 Festival은 제외하고 ID ASC로 정렬한다.
- 생성된 Festival이 없으면 빈 배열을 반환한다.

### 📌 현재 확인된 결정 사항

#### ImportBatch / preview

- `ImportBatch.preview`는 DB text 한 건으로 저장한다. — DEC-0055
- preview 유효시간은 30분이다. — DEC-0055, DEC-0076
- 저장용 preview의 현재 지원 버전은 `schemaVersion: 1`이다. — Issue #37
- API Response DTO와 저장용 preview 모델은 분리한다. — Issue #37
- 저장된 preview에는 원본 payload, normalized payload, 매칭 정보와 commit 연결 정보가 포함되어 원본 CSV 재업로드 없이 처리할 수 있다. — Issue #37
- `ImportBatch.type`은 `BUNDLE`, `FESTIVALS`, `LINEUPS`, `ARTISTS`다. — DEC-0076
- conflict policy는 `UPDATE`, `SKIP`이며 기본값은 `UPDATE`다. — DEC-0076, Issue #37

#### Commit 처리

- 반영 순서는 `artists → festivals → lineups`다. — DOC-0007
- 전체 반영은 하나의 트랜잭션으로 수행하고 중간 실패 시 rollback한다. — DOC-0007
- Host는 자동 생성하지 않는다. — DOC-0007, Issue #37
- Artist는 필요한 경우 생성하고 검수 상태를 보존한다. — DOC-0007
- 신규 Festival은 미발행 상태로 저장하고 commit에서 `publishedAt`을 설정하지 않는다. — DOC-0007
- 이미 발행된 Festival은 자동 SKIP하며 수정하지 않는다. — DOC-0007
- Lineup은 Festival 단위 전체 교체한다. — DOC-0007
- Lineup 전체 교체 정책상 Lineup UPDATE 집계는 항상 0이다. — DOC-0007
- Lineup의 Artist는 nullable이며 시크릿 게스트를 null Artist로 표현할 수 있다. — DEC-0074, DOC-0005
- 가변 입력 어휘는 DB CHECK보다 애플리케이션 계층에서 검증한다. — DOC-0005

#### 감사 이력

- 감사 행 식별자는 `rowNumber`가 아니라 `line`을 사용한다. — DEC-0077
- `line`은 header를 제외한 section별 데이터 행 기준 1부터 시작한다. — DEC-0077
- 감사 action은 `CREATE`, `UPDATE`, `SKIP`이며 SKIP도 반드시 저장한다. — DEC-0077
- INVALID는 현재 감사 action 계약에 포함되지 않는다. — DEC-0077
- Festival / Lineup의 `importKey`는 CSV `import_key`, Artist의 `importKey`는 name을 사용한다. — DEC-0077
- Festival / Artist FK는 nullable이며 삭제 후에도 payload와 문자열 식별자를 유지한다. — DEC-0077
- 감사 payload는 `ImportCommitPayload` JSONB, NOT NULL이며 원본 CSV 행을 snake_case로 저장한다. — DEC-0077
- `ticket_open_at`은 감사 payload에서 원문 String으로 보존한다. — DEC-0077
- `committedAt`은 Service가 실제 commit 시각을 `Instant`로 공급한다. — DEC-0077

#### 부분 commit과 검증

- `lines` 생략 시 전체 preview의 commit 가능한 행을 모두 선택한다.
- artists / festivals는 정상 row 단위 선택을 허용한다.
- lineups는 Festival 단위로 원자적으로 선택한다.
- 선택하지 않은 row는 도메인 반영 및 감사 이력 대상이 아니다.
- 선택 row의 INVALID 또는 미해결 blocker만 commit을 막는다.
- 전체 선택에서는 INVALID/blocker가 하나라도 있으면 commit을 거부한다.
- preview action의 의미가 CREATE↔UPDATE 등으로 달라지면 재계산하지 않고 `IMPORT_PREVIEW_STALE`로 거부한다.
- Host, Artist/name/alias, Festival importKey/publishedAt, Lineup 제약과 row 의존성을 bulk 재검증한다.

#### 동시성, 시각과 preview lifecycle

- `ImportBatch` commit 조회에 `PESSIMISTIC_WRITE`를 사용한다.
- lock 획득 후 `committedAt`을 다시 확인하며 첫 요청 성공 후 후속 요청은 `IMPORT_ALREADY_COMMITTED`를 반환한다.
- optimistic locking용 version 필드와 Flyway migration은 추가하지 않는다.
- Service에서 commit당 하나의 `Instant`를 생성한다.
- 같은 Instant를 `ImportBatch.committedAt`, 모든 `ImportCommitRow.committedAt`, Response `committedAt`에 사용한다.
- commit 성공 후 `ImportBatch.preview`를 삭제하거나 null 처리하지 않고 유지한다.
- 만료 preview cleanup은 별도 이슈로 처리한다.

#### 응답

- `importId`는 `Long`이며 별도 공개 ID를 도입하지 않는다.
- section별 결과는 `created`, `updated`, `skipped`, `failed`를 포함한다.
- 성공 응답의 `failed`는 0이며 Lineup의 `updated`도 0이다.
- `createdFestivalIds`는 실제 CREATE Festival ID만 ID ASC로 반환한다.

#### API 공통

- `/api` prefix를 사용하지 않는다. — DEC-0084
- API Enum 문자열은 영문 대문자를 사용한다. — DEC-0081
- `/admin/**`는 관리자 JWT 인증 계약을 따른다. — DEC-0082, DEC-0083
- `IMPORT_NOT_FOUND`, `IMPORT_ALREADY_COMMITTED`, `IMPORT_EXPIRED`의 상태 코드는 DOC-0008을 따른다.

- 지원하지 않는 schemaVersion과 손상된 preview를 명시적 Import 오류로 처리한다.
- 존재하지 않거나 이미 commit되었거나 만료된 batch를 확정된 오류로 처리한다.
- artists / festivals row 부분 선택과 Lineup Festival 단위 원자성 규칙을 검증한다.
- 선택한 신규 Festival / Artist 의존 row가 누락되면 commit을 거부한다.
- 선택 row의 INVALID 또는 미해결 blocker만 commit을 막는다.
- commit 직전 현재 DB 상태를 일괄 재조회하고 stale preview를 `IMPORT_PREVIEW_STALE`로 거부한다.
- Artist → Festival → Lineup 순서로 실제 DB에 반영한다.
- 신규 Artist와 Festival의 생성 ID가 같은 트랜잭션의 Lineup에 연결된다.
- Artist alias 소유권 충돌 시 전체 transaction을 거부한다.
- Festival hashtag는 빈 값이면 유지하고 값이 있으면 중복 제거 후 전체 교체한다.
- 이미 발행된 Festival은 SKIP하고 실제 action을 감사 기록한다.
- 발행된 Festival의 선택 Lineup은 commit을 거부한다.
- Lineup은 데이터 유실 없이 Festival 단위 전체 교체 규칙을 지킨다.
- CREATE / UPDATE / SKIP 행의 `ImportCommitRow`가 원본 payload와 함께 저장된다.
- 성공 시 `ImportBatch.committedAt`이 실제 commit `Instant`로 갱신된다.
- 실패 시 도메인 변경, 감사 이력, committedAt이 모두 rollback된다.
- pessimistic write lock으로 동시 commit 요청에서도 같은 batch가 한 번만 반영된다.
- commit당 하나의 Instant를 batch, 감사 행, 응답에 공통 사용한다.
- commit 성공 후 기존 preview가 유지된다.
- commit API 응답이 확정된 DTO 계약과 일치한다.
- Issue #37의 upload/preview API 계약과 동작이 깨지지 않는다.

- Lineup 결과 `updated = 0`
- SKIP 도메인 미변경
- 이미 발행된 Festival 미변경 및 실제 action SKIP 처리

#### 부분 commit

- `lines` 생략 시 전체 commit 가능한 행 선택
- artists row 부분 선택
- festivals row 부분 선택
- 존재하지 않는 section/line 요청 오류
- Lineup Festival 단위 전체 선택
- 한 Festival의 Lineup 일부 선택 거부
- 신규 Artist 의존 row 미선택 거부
- 신규 Festival 의존 row 미선택 거부
- 선택되지 않은 행의 도메인 및 감사 데이터 미생성

#### preview 및 사전 검증

- ImportBatch 없음
- 이미 committed된 ImportBatch
- 만료된 ImportBatch
- preview null/empty
- unsupported `schemaVersion`
- malformed preview JSON
- 선택되지 않은 INVALID/blocker row는 commit을 막지 않음
- 선택된 INVALID row는 `IMPORT_UNCOMMITTABLE`
- 선택된 미해결 blocker는 `IMPORT_UNCOMMITTABLE`
- preview 이후 Host 삭제·변경
- preview 이후 Artist / Alias 매칭 변경
- stale CREATE↔UPDATE 변경은 `IMPORT_PREVIEW_STALE`
- preview 이후 Festival 발행 시 Festival 실제 action SKIP
- 발행 Festival Lineup 선택 시 commit 거부
- ArtistAlias ownership 충돌 시 stale 오류 및 rollback

#### 감사 이력

- CREATE / UPDATE / SKIP 각 행의 ImportCommitRow 저장
- INVALID 행이 감사 action으로 저장되지 않음
- section / line / importKey 정확성
- nullable Festival / Artist FK
- 원본 snake_case payload JSONB 저장
- `ticket_open_at` 원문 보존
- commit 실행 action과 감사 action 일치
- 동일 commit 시각 사용
- partial commit의 실제 CREATE만 `createdFestivalIds`에 포함

#### 트랜잭션 및 동시성

- Artist 반영 실패 시 전체 rollback
- Festival 반영 실패 시 Artist 포함 전체 rollback
- Lineup 반영 실패 시 Artist / Festival 포함 전체 rollback
- ImportCommitRow 저장 실패 시 도메인 변경 전체 rollback
- committedAt 갱신 실패 시 전체 rollback
- row validation 실패가 부분 반영을 남기지 않음
- pessimistic lock 동시 commit 시 한 요청만 성공하고 후속 요청은 `IMPORT_ALREADY_COMMITTED`

#### 응답 및 회귀

- result 집계 정확성
- createdFestivalIds에 실제 CREATE Festival만 ID ASC 포함
- committedAt UTC ISO-8601 직렬화
- commit 후 ImportBatch.preview 유지
- FestivalHashtag CSV 값 전체 교체 및 빈 값 유지
