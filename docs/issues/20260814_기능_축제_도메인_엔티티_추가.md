## 제목

🚀 [기능요청][엔티티] 축제 도메인 엔티티와 스키마 추가

## 본문

## 📝 현재 문제점

- 엔티티가 하나도 없다. JPA 설정이 스키마 검증 모드라 테이블이 없으면 애플리케이션이 기동되지 않는다
- 크롤러가 축제 번들을 이미 내보내고 있는데 받아서 저장할 곳이 없다
- 축제 목록과 상세 화면이 요구하는 데이터의 저장 구조가 정해져 있지 않다

## 🛠️ 해결 방안 / 제안 기능

- 데이터 모델 초안의 축제 영역을 만든다. 주최, 축제, 축제 해시태그 세 가지이며 서로만 참조해서 밖으로 나가는 연결이 없다
- 아티스트·라인업·집계 뷰는 별도 이슈로 분리한다. 라인업이 축제와 아티스트 양쪽을 참조하므로 축제가 먼저 들어가야 한다
- 입장 정책, 티켓 종류, 수집 상태는 크롤러가 쓰는 값 목록과 동일하게 고정한다
- 생성·수정 시각은 공통 엔티티로 분리한다. 다만 임포트가 통째로 교체하는 테이블에는 상속하지 않는다 — 마지막 임포트 시각이 등록 시각으로 오해되기 때문이다
- 마이그레이션 버전 번호는 V2를 쓴다. 아티스트·라인업 이슈가 V3를 쓴다
- 축제 위치 좌표는 크롤러가 지오코딩해 내보내는 것으로 설계됐으나 현재 산출물에 해당 컬럼이 없다. 좌표가 없으면 발행할 수 없으므로 크롤러 쪽 대응이 별도로 필요하다

## ⚙️ 작업 내용

- 공통 엔티티 정의 — 생성·수정 시각 자동 기록
- 주최 · 축제 · 축제 해시태그 엔티티 정의
- 축제 도메인 스키마 마이그레이션 추가 (V2)
- 애플리케이션 기동으로 스키마 검증 통과 확인
