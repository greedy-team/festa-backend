## 제목

✨ [기능요청][관리자][임포트] CSV 업로드·검증 및 미리보기 API 추가

## 본문

## 🧩 배경

- `festa-crawler`는 `festivals.csv`, `lineup.csv`, `artists.csv`를 생성하지만, 현재 `festa-backend`에는 이를 업로드하고 검증하는 API가 없다.
- 관리자가 CSV 내용을 검토하지 않은 채 바로 DB에 반영하면 잘못된 주최 매칭, 중복 아티스트, 잘못된 열거값과 날짜 형식 등이 실제 서비스 데이터에 반영될 수 있다.
- 따라서 실제 데이터 반영 전에 CSV를 파싱·검증하고 기존 DB와 비교하여 `CREATE`, `UPDATE`, `SKIP` 예상 결과와 blocker/warning을 확인할 수 있는 preview 단계가 필요하다.
- 현재 백엔드에는 `ImportBatch`, `ImportBatchType`, `ImportConflictPolicy`, `Artist`, `ArtistAlias`, `Festival`, `FestivalHashtag`, `Lineup`, `Host` Entity와 대응 Flyway 스키마가 존재한다.
- 반면 Import 전용 Repository, Service, Controller, DTO, CSV parser/validator는 아직 없다.
- 이번 이슈는 3단계로 분리한 임포트 기능 중 첫 번째 단계다. 실제 반영과 감사 이력은 후속 commit 이슈에서, 임포트 이력 조회와 만료 정리는 별도 history 이슈에서 구현한다.

## 🎯 목표

관리자가 `festa-crawler`가 생성한 CSV를 bundle 또는 single 방식으로 업로드하면 백엔드가 다음 흐름을 수행하고 실제 반영 전 preview를 반환하도록 한다.

```text
festa-crawler
→ CSV
→ 관리자 업로드
→ 백엔드 파싱
→ 형식/값 검증
→ 기존 DB와 매칭
→ CREATE / UPDATE / SKIP / INVALID 예상 action 판정
→ blocker / warning 생성
→ preview 생성
→ ImportBatch 저장
→ 관리자에게 preview 반환
```

이번 단계에서는 실제 `Artist`, `Festival`, `Lineup` 데이터를 생성·수정·삭제하지 않는다.

## 📋 API 개요

### 1. Bundle upload

- Method: `POST`
- Endpoint: `/admin/imports/bundle`
- Content-Type: `multipart/form-data`
- 인증: 관리자 JWT 인증 필요
- form field: `onConflict` 선택, 기본값 `UPDATE`, 허용값 `UPDATE` / `SKIP`
- 파일:
  - `festivals.csv`: 필수
  - `lineup.csv`: 필수
  - `artists.csv`: 선택

세 CSV를 하나의 `ImportBatchType.BUNDLE` batch로 파싱·검증하고 통합 preview를 생성한다.

### 2. Single upload

- Method: `POST`
- Endpoint: `/admin/imports/{type}`
- Content-Type: `multipart/form-data`
- 인증: 관리자 JWT 인증 필요
- form field: `onConflict` 선택, 기본값 `UPDATE`, 허용값 `UPDATE` / `SKIP`
- `type`:
  - `festivals`
  - `lineups`
  - `artists`
- 파일: 해당 type의 CSV 한 개

Path variable은 외부 API 계약에 맞춰 소문자를 사용하고 내부에서는 다음 `ImportBatchType`으로 변환한다.

| Path variable | ImportBatchType |
| --- | --- |
| `festivals` | `FESTIVALS` |
| `lineups` | `LINEUPS` |
| `artists` | `ARTISTS` |

bundle과 single은 CSV parser, section validator, DB matching, action 판정, preview 생성 및 `ImportBatch` 저장 로직을 공유한다.

### 공통 처리

- UTF-8 encoding 검증
- UTF-8 BOM 허용 및 parser 진입 전 제거
- 빈 파일 및 데이터 행 없음 검증
- 파일별 header 정확 일치 검증
- quoted comma, escaped quote, 줄바꿈을 지원하는 CSV parsing
- section별 row model 변환
- 필수값, 날짜/시간, URL, 열거값, 행 간 참조 검증
- Host / Artist / ArtistAlias / Festival DB matching
- `CREATE`, `UPDATE`, `SKIP`, `INVALID` 예상 action 판정
- blocker / warning 생성
- API 응답용 preview 생성
- 후속 commit에서 재사용할 저장용 preview JSON 생성
- `ImportBatch` 저장 및 30분 만료 시각 계산

## 🧱 Preview 설계 원칙

- API 응답 DTO와 `ImportBatch.preview`에 저장할 내부 모델을 구분한다.
- 저장용 preview 최상위에는 `schemaVersion: 1`을 둔다.
- 저장용 preview는 후속 `POST /admin/imports/{importId}/commit`이 원본 CSV를 다시 받지 않고도 반영 작업을 수행할 수 있는 정보를 보존해야 한다.
- 최소한 다음 정보가 저장되어야 한다.
  - section
  - `line`: header를 제외한 section별 데이터 행 번호, 1부터 시작
  - 원본 import key
  - 예상 action
  - 정규화된 입력값
  - 원본 CSV row payload
  - 기존 Host / Artist / Festival 매칭 결과
  - blocker / warning 및 SKIP 사유
  - conflict policy
- preview summary는 `toCreate`, `toUpdate`, `toSkip`, `invalid`를 사용한다.
- Artist 매칭 결과 id는 `matchedArtistId`를 사용하며 신규 생성 예정 Artist는 null일 수 있다.
- CREATE 대상의 실제 DB id는 preview 시점에 존재하지 않을 수 있으므로 필수 저장값으로 가정하지 않는다.
- commit 시점의 DB 상태 변경 가능성을 고려하여 preview action은 예상값이며, 후속 commit 이슈에서 트랜잭션 내부 재검증을 수행한다.

## 🧭 Validation 및 판정 기준

### 파일 검증

- multipart part 누락을 검증한다.
- 빈 파일과 header만 있고 데이터가 없는 CSV를 검증한다.
- UTF-8이 아닌 파일은 `IMPORT_INVALID_CSV_ENCODING`으로 처리한다.
- UTF-8 BOM은 허용하고 제거한 뒤 정상 UTF-8 CSV로 처리한다. BOM만으로 encoding 오류를 반환하지 않는다.
- 파일별 CSV header가 계약과 정확히 일치하지 않으면 `IMPORT_INVALID_CSV_HEADER`로 처리한다.
- CSV quoting과 escape를 지원하는 검증된 라이브러리를 사용하고 단순 `String.split(",")` 방식은 사용하지 않는다.

### Host matching

- Host는 임포트 과정에서 자동 생성하지 않는다.
- CSV Host 이름의 앞뒤 whitespace를 trim한 뒤 기존 `Host.name`과 exact match한다.
- `Host.shortName`, 축약명 또는 유사도 기반 자동 매칭은 사용하지 않는다.
- 매칭 실패 또는 복수 후보는 실제 반영을 막는 blocker로 표현한다.

### Artist matching

- 입력 이름의 앞뒤 whitespace를 trim한 뒤 `Artist.name` exact match를 우선하고, 없으면 `ArtistAlias.name` exact match를 사용한다.
- 둘 다 같은 Artist를 가리키면 해당 Artist로 매칭한다.
- 서로 다른 Artist 후보가 생기면 임의 선택하지 않고 blocker와 `UNRESOLVED`로 표시한다.
- 매칭되지 않으면 신규 Artist 생성 예정 상태로 preview한다.
- preview의 `artistMatchStatus`는 `MATCHED`, `NEW`, `UNRESOLVED`를 사용하고 기존 Artist id는 `matchedArtistId`로 반환한다.

### Festival matching

- 백엔드는 `import_key`를 생성하지 않고 crawler가 전달한 `{university}-{year}` 값을 그대로 사용한다.
- `Festival.importKey`를 기준으로 기존 Festival과의 CREATE/UPDATE/SKIP 후보를 판정한다.
- 같은 업로드 안의 중복 `import_key`는 오류/blocker로 처리한다.
- DB에 동일 key가 있으면 `onConflict`에 따라 UPDATE 또는 SKIP 후보로 판정한다.
- 복수 `image_urls` 원본 배열은 preview 응답과 저장 모델에 보존한다. 대표 이미지 후보는 `poster_url`을 우선하고, 비어 있으면 첫 번째 `image_urls`를 사용한다.
- Host가 연결되지 않은 Festival은 실제 반영할 수 없는 blocker로 표시한다.

### Lineup validation

- Festival은 CSV `import_key`로 식별한다.
- Artist가 공개된 row는 Artist 매칭 결과를 포함한다.
- 시크릿 게스트는 현재 Entity 구조에 따라 nullable `Lineup.artist`로 저장 가능한 형태로 preview한다.
- `flag != OK`인 Festival의 lineup row는 crawler가 산출하지 않는 계약을 전제로 검증한다.
- 실제 Lineup 생성이나 Festival 단위 전체 교체는 이번 이슈에서 수행하지 않는다.

### 날짜/값 및 UPDATE 규칙

- `ticket_open_at`은 ISO-8601 datetime만 허용하고 date-only 값은 허용하지 않는다.
- offset 포함 형식을 canonical로 하며 `Instant`로 변환한다. 현재 crawler가 출력하는 offset 없는 datetime은 `Asia/Seoul`로 해석한다.
- 원본 `ticket_open_at` 문자열은 preview/audit payload에 그대로 보존한다.
- `discovery` canonical 값은 `MANUAL`, `SITEMAP`, `SEARCH`, `PASTED`다. DB CHECK 제약은 추가하지 않는다.
- UPDATE에서 선택 필드의 빈 문자열/null은 기존 값을 삭제하지 않고 유지한다. 명시적인 값만 변경 예정으로 표시한다.
- Artist alias 등 집합형 값은 기존 값과 CSV 값의 합집합으로 preview한다.

## 📌 현재 확인된 결정 사항

- crawler의 `festivals.csv`, `lineup.csv`, `artists.csv`를 별도 export 변환 단계 없이 백엔드 업로드 계약과 한 벌로 유지한다. 근거: DEC-0049, DOC-0007.
- `flag != OK`인 Festival의 lineup row는 crawler가 CSV에 산출하지 않는다. 근거: DEC-0050.
- preview는 별도 row 테이블이나 Redis가 아니라 `ImportBatch.preview`의 단일 PostgreSQL `text` / Java `String` 값으로 저장한다. 근거: DEC-0055, DEC-0076, DOC-0005.
- preview 유효시간은 30분이며 `expiresAt = uploadedAt + 30분`으로 계산한다. `uploadedAt`은 auditing이 아니라 Service가 전달한다. 근거: DEC-0055, DEC-0076.
- 만료 전 preview는 commit에서 재사용할 수 있어야 하며, 만료 후에도 ImportBatch 자체는 이력으로 남긴다. 만료 preview cleanup은 후속 이슈 범위다. 근거: DEC-0055.
- `ImportBatch.type`은 `BUNDLE`, `FESTIVALS`, `LINEUPS`, `ARTISTS`다. 근거: DEC-0076.
- `ImportBatch.onConflict`는 `UPDATE`, `SKIP`이다. 근거: DEC-0076.
- `ImportBatch.uploadedByAdmin`은 관리자 삭제 후에도 batch 이력을 보존하기 위해 nullable LAZY 관계다. 근거: DEC-0076.
- 가변 값 어휘는 PostgreSQL CHECK 제약으로 고정하지 않고 애플리케이션 preview validation에서 검증한다. 근거: DEC-0057, DOC-0005.
- API에 노출하는 Enum 값은 영문 `UPPER_SNAKE_CASE`이며 표시용 문구는 프론트엔드가 소유한다. 근거: DEC-0081.
- `flag` canonical 값은 `OK`, `FETCH_FAILED`, `EMPTY_BODY`, `EXTRACT_FAILED`, `MISMATCH`, `NO_CANDIDATE`, `NO_SOURCE` 7종을 영문 대문자로 사용한다. 근거: DEC-0081, DOC-0007, cluster-crawler-pipeline.
- preview 및 향후 감사 이력의 행 번호는 `rowNumber`가 아니라 header를 제외한 section별 데이터 행 기준 `line`을 사용하며 1부터 시작한다. 근거: DEC-0077.
- 예상 action과 향후 감사 action은 `CREATE`, `UPDATE`, `SKIP`을 사용하고 SKIP도 추적 가능한 데이터로 유지한다. 근거: DEC-0077.
- Festival과 Lineup의 감사 식별자는 CSV `import_key`, Artist의 감사 식별자는 `name`을 사용한다. 근거: DEC-0077.
- 원본 CSV row payload는 snake_case key를 유지하고 `ticket_open_at` 원문은 향후 감사 payload에서 `String`으로 보존한다. 근거: DEC-0077.
- Host는 임포트 과정에서 자동 생성하지 않는다. 매칭되지 않은 Host는 선행 등록이 필요한 blocker다. 근거: DOC-0007.
- Artist 분류는 `category`가 아니라 `genre` 하나만 사용한다. 근거: DEC-0040, DEC-0049.
- API 경로에는 `/api` prefix를 붙이지 않는다. 근거: DEC-0084.
- `/admin/**`는 별도 권한 등급 없이 관리자 JWT 인증을 요구한다. 인증 기능 자체 구현은 이번 범위가 아니다. 근거: DEC-0082, DEC-0083.
- 현재 `Lineup.artist`는 nullable이므로 시크릿 게스트를 Artist 연결 없이 표현할 수 있다. 근거: DEC-0074, DOC-0005.
- 현재 존재하는 `ImportBatch`, `ImportBatchType`, `ImportConflictPolicy`, `Artist`, `ArtistAlias`, `Festival`, `FestivalHashtag`, `Lineup`, `Host`를 재사용하고 preview 편의를 위해 불필요하게 Entity를 변경하지 않는다.
- preview summary 필드명은 `toCreate`, `toUpdate`, `toSkip`, `invalid`이고 row action은 `CREATE`, `UPDATE`, `SKIP`, `INVALID`다.
- Artist 매칭 id 필드명은 `matchedArtistId`이며 신규 생성 예정 Artist에서는 null일 수 있다.
- `image_urls` 원본 배열은 preview 응답과 저장 모델에 보존한다. 대표 이미지 후보는 `poster_url`을 우선하고, 없으면 첫 번째 `image_urls`를 사용한다. 나머지 이미지를 저장할 Entity/테이블은 이번 이슈에서 추가하지 않는다.
- 백엔드는 `import_key`를 생성하지 않고 crawler가 전달한 canonical `{university}-{year}` 값을 그대로 사용한다. 업로드 내부 중복은 blocker이며 DB 충돌은 `onConflict`에 따라 UPDATE/SKIP 후보로 판정한다. 동일 Host·year 복수 Festival의 key 형식 변경은 별도 crawler 계약 이슈다.
- UTF-8 BOM은 허용하고 제거한 뒤 parsing한다.
- `ticket_open_at`은 ISO-8601 datetime을 사용한다. offset 포함 형식은 `Instant`로 변환하며, 현재 crawler가 출력하는 offset 없는 datetime은 `Asia/Seoul`로 해석한다. date-only는 허용하지 않고 원문은 보존한다.
- `discovery` canonical 값은 `MANUAL`, `SITEMAP`, `SEARCH`, `PASTED`이며 DB CHECK는 추가하지 않는다.
- 저장용 preview 최상위에는 `schemaVersion: 1`을 두고 API 응답 DTO와 저장 모델을 분리한다.
- Host는 입력값을 trim한 뒤 `Host.name` exact match만 사용한다. `shortName`, 축약명, 유사도 자동 매칭 및 Host 자동 생성은 사용하지 않으며 실패·복수 후보는 `HOST_NOT_FOUND` 계열 blocker로 처리한다.
- Artist는 trim 후 `Artist.name` exact match를 우선하고 없으면 `ArtistAlias.name` exact match를 사용한다. 서로 다른 Artist 후보는 blocker와 `UNRESOLVED`, 미매칭은 `NEW`로 표시하며 `artistMatchStatus`는 `MATCHED`, `NEW`, `UNRESOLVED`를 사용한다.
- UPDATE에서 선택 필드의 빈 문자열/null은 기존 값을 유지한다. 명시적인 값만 변경 예정이며 집합형 alias는 기존 값과 CSV 값의 합집합으로 처리한다.
- multipart 제한은 파일 하나 `5MB`, 전체 요청 `20MB`이며 초과 시 `PAYLOAD_TOO_LARGE`를 사용한다.
- `onConflict`는 multipart form field로 받는 선택값이고 기본값은 `UPDATE`, 허용값은 `UPDATE`, `SKIP`이다.

- `POST /admin/imports/{type}`로 `festivals`, `lineups`, `artists` 단일 CSV를 업로드하면 해당 section preview를 반환한다.
- bundle과 single이 동일한 parser, validator, DB matching 및 preview 생성 핵심 로직을 재사용한다.
- UTF-8 BOM을 허용·제거하고, UTF-8 encoding, 빈 파일, 데이터 행 없음, header, CSV 문법, 필수값, 날짜/시간, URL, 열거값 및 참조 관계를 검증한다.
- 오류는 공통 `ErrorResponse` 형식과 Import 도메인 ErrorCode로 반환한다.
- 기존 Host / Artist / ArtistAlias / Festival을 조회하여 예상 `CREATE`, `UPDATE`, `SKIP`, `INVALID`와 blocker/warning을 계산하고 summary를 `toCreate`, `toUpdate`, `toSkip`, `invalid`로 반환한다.
- Host 매칭 실패 시 Host를 자동 생성하지 않고 blocker로 반환한다.
- Host는 trim 후 `Host.name` exact match만 사용하고 `shortName`은 자동 매칭하지 않는다.
- Artist 매칭은 name exact match를 우선하고 alias exact match로 fallback하며, 충돌은 `UNRESOLVED`로 반환한다.
- Festival `image_urls` 원본 배열을 보존하고 `poster_url` 우선, 첫 image URL fallback으로 대표 이미지 후보를 계산한다.
- UPDATE에서 빈 선택 필드는 기존 값을 유지하고 alias 집합은 합집합 처리한다.
- preview 요청으로 실제 Artist, ArtistAlias, Festival, FestivalHashtag, Lineup 데이터가 생성·수정·삭제되지 않는다.
- 성공 시 `ImportBatch`가 요청 유형, 파일명, conflict policy, preview, 업로더, uploadedAt, expiresAt과 함께 저장된다.
- `expiresAt`은 Service가 전달한 `uploadedAt`으로부터 정확히 30분 뒤다.
- `ImportBatch.preview`는 PostgreSQL text 한 건으로 저장된다.
- 저장된 preview만으로 후속 commit이 section, line, importKey, 예상 action, 정규화 값, 원본 payload, 매칭 결과와 blocker를 복원할 수 있다.
- 저장용 preview는 `schemaVersion: 1`을 포함하고 직렬화·역직렬화 왕복 테스트가 통과한다.
- 파일별 `5MB`, 전체 multipart 요청 `20MB` 제한과 `PAYLOAD_TOO_LARGE` 오류가 적용된다.
- `onConflict`를 생략하면 `UPDATE`가 적용되고 `UPDATE`, `SKIP`만 허용한다.
- 관리자 인증 기능이 적용된 환경에서는 인증되지 않은 요청이 공통 401 응답을 따른다.
- 관련 Repository, parser, validator, Service, Controller 테스트와 전체 빌드가 통과한다.

## 🧪 테스트 항목

### Bundle API

- festivals + lineup 필수 파일 업로드 성공
- artists 선택 파일 포함 업로드 성공
- festivals 누락
- lineup 누락
- artists 누락 허용
- 세 section의 preview가 하나의 ImportBatch에 저장됨

### Single API

- `festivals`, `lineups`, `artists` 각각 업로드 성공
- 지원하지 않는 type
- type과 업로드 파일 section 불일치
- bundle과 동일 parser/validator를 사용하는 계약 테스트

### Encoding / 파일

- 정상 UTF-8
- UTF-8 BOM 입력 허용 및 제거
- UTF-8이 아닌 encoding
- 0 byte 파일
- header만 있는 파일
- 파일별 `5MB` 제한 초과
- bundle 전체 요청 `20MB` 제한 초과

### CSV parser / header

- 정상 header
- 필수 header 누락
- 알 수 없는 header 추가
- header 순서 정책
- quoted comma
- escaped quote
- quoted multiline value
- trailing empty column
- malformed CSV
- section별 `line`이 header 제외 1부터 증가

### Section validation

- 필수값 누락
- 잘못된 LocalDate
- offset 포함 `ticketOpenAt`을 `Instant`로 변환
- offset 없는 crawler `ticketOpenAt`을 `Asia/Seoul`로 해석
- date-only `ticketOpenAt` 거부 및 원문 보존
- 잘못된 URL
- 잘못된 enum/어휘
- flag 7종 정상 입력과 알 수 없는 flag
- discovery `MANUAL`, `SITEMAP`, `SEARCH`, `PASTED`와 알 수 없는 discovery
- Festival 기간 역전
- 중복 import_key
- Lineup이 참조하는 Festival import_key 없음
- 공개 Artist row의 Artist 정보 누락
- 시크릿 게스트의 nullable Artist 처리

### DB matching / action

- trim 후 Host.name exact match
- Host.shortName은 자동 매칭하지 않음
- Host 매칭 실패 blocker
- Host 복수 후보 blocker
- Host가 자동 생성되지 않음
- 기존 Festival importKey 매칭 UPDATE 후보
- 신규 Festival CREATE 후보
- Artist.name 우선 매칭
- ArtistAlias.name fallback
- name과 alias가 서로 다른 Artist에 매칭되는 충돌은 blocker와 `UNRESOLVED`
- 신규 Artist CREATE 후보, `NEW`, nullable `matchedArtistId`
- `onConflict`의 `UPDATE`, `SKIP` 및 생략 시 `UPDATE`
- `CREATE`, `UPDATE`, `SKIP`, `INVALID` row action과 `toCreate`, `toUpdate`, `toSkip`, `invalid` 집계
- UPDATE에서 빈 값은 기존 값 유지
- Artist alias 집합은 기존 값과 CSV 값의 합집합
- 중복 Festival `import_key` blocker
- DB importKey 충돌 시 conflict policy에 따른 UPDATE/SKIP
- `poster_url` 존재 시 대표 이미지 후보로 사용
- `poster_url` 부재 시 첫 `image_urls` fallback 및 원본 배열 보존

### Preview / ImportBatch

- API response DTO 생성
- `schemaVersion: 1` 저장용 preview JSON 직렬화·역직렬화 왕복
- 저장용 preview에 section, line, importKey, action, 원본 payload, 정규화 값, 매칭 결과, blocker/warning 포함
- `schemaVersion: 1` 검증
- fileNames와 ImportBatchType 저장
- uploadedByAdmin nullable 관계
- uploadedAt 저장
- expiresAt이 uploadedAt보다 정확히 30분 뒤
- 실제 Artist / Festival / Lineup 데이터 미변경

### Error response

- `IMPORT_EMPTY_CSV`
- `IMPORT_INVALID_CSV_ENCODING`
- `IMPORT_INVALID_CSV_HEADER`
- 지원하지 않는 type 및 잘못된 요청 파라미터
- `PAYLOAD_TOO_LARGE`
- 공통 `errorCode`, `message`, `status`, `instance` 형식
