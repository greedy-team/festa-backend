## 본문

## 📝 현재 문제점

- 주최는 크롤러가 만들지 않는다. 임포트는 주최를 자동으로 만들지 않고 이름으로 맞춰보기만 하므로, 누군가 먼저 등록해두어야 축제가 주최에 연결된다
- 지금은 등록할 수단이 없어 데이터베이스에 직접 넣는 것 말고는 방법이 없다
- API가 하나도 없어서 앞서 정한 에러 응답 규약이 실제로 동작하는지 확인된 적이 없다

## 🛠️ 해결 방안 / 제안 기능

- 관리자용 주최 등록·목록·수정·삭제 API를 만든다
  - 등록 — POST /api/admin/hosts
  - 목록 — GET /api/admin/hosts
  - 수정 — PATCH /api/admin/hosts/{id}
  - 삭제 — DELETE /api/admin/hosts/{id}
- 축제가 하나라도 등록된 주최는 삭제하지 않는다. 축제가 주최를 참조하고 있어 데이터베이스가 삭제를 거부하는데, 걸러내지 않으면 잘못된 요청이 서버 오류로 나간다. 전용 에러 코드로 응답한다
- 수정은 보내온 항목만 반영한다. 항목을 보내지 않으면 기존 값을 그대로 두고, 빈 값으로 보내면 비운다
- 이름은 임포트가 축제와 주최를 맞출 때 쓰는 키다. 중복을 허용하지 않으며, 이미 있는 이름으로 등록하면 전용 에러 코드로 응답한다
- 값 검증은 요청 본문에서 한다. 이름이 100자를, 지역이 50자를 넘으면 각각의 에러 코드로 응답한다. 데이터베이스에는 길이 제한을 두지 않는다 — 이 오류는 요청 검증 단계에서 걸러야 하는 것이고, 데이터베이스까지 도달하면 잘못된 요청이 아니라 서버 오류가 되기 때문이다
- 목록은 페이지로 나눈다
- 에러는 앞서 정한 공통 규약을 그대로 쓴다. 주최 전용 에러 코드는 이 작업에서 도메인 코드 목록으로 추가한다
- 주최 유형 관련 에러 코드는 쓰지 않는다. 유형 항목 자체를 두지 않기로 했다

## ⚙️ 작업 내용

- 주최 저장소·서비스·컨트롤러 추가
- 등록·목록·수정 각각의 요청과 응답 형식 정의
- 공통 페이지 응답 형식 추가 — 목록 API가 처음이라 여기서 만든다. 아티스트·축제 목록도 같은 형식을 쓴다
- 주최 도메인 에러 코드 정의
- 요청 값 검증 연결 — 이름과 지역의 길이, 이름 중복, 없는 주최 수정, 축제가 남은 주최 삭제
- 최소 보안 설정 추가

## ⚠️ 주의

이 작업의 API는 인증 없이 열린다. 지금은 보안 설정이 아예 없어 컨트롤러를 만드는 순간 모든 경로가 기동할 때마다 새로 만들어지는 임시 비밀번호로 잠기며, 그대로면 개발이 불가능하다. 그래서 우선 열어두고 진행한다.

관리자 인증은 별도 이슈로 다룬다. 배포 전에 반드시 교체해야 한다.
