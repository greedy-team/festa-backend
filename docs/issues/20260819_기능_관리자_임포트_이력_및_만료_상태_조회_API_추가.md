## 제목

✨ [기능요청][관리자][임포트] 임포트 이력 및 만료 상태 조회 API 추가

## 본문

### 📌 배경

Issue #37에서 관리자가 CSV를 업로드하면 파싱·검증·DB 매칭 결과가 `ImportBatch.preview`에 저장되고, Issue #39에서는 저장된 preview를 기반으로 실제 데이터를 반영한 뒤 행별 실행 결과를 `ImportCommitRow`에 감사 이력으로 저장한다.

현재는 업로드 및 commit 단건 처리 API만 있고, 관리자가 누가 언제 어떤 파일을 업로드했는지, preview가 아직 유효한지, commit이 완료됐는지, 또는 30분이 지나 만료됐는지를 목록으로 확인할 API가 없다.

`ImportBatch`에는 `type`, `fileNames`, `uploadedByAdmin`, `uploadedAt`, `expiresAt`, `committedAt`이 이미 존재한다. 따라서 별도 status 컬럼이나 history 테이블을 추가하지 않고 현재 필드에서 상태를 파생하고, 실제 commit 결과는 `ImportCommitRow`의 section/action을 집계하여 제공한다.

### 🎯 목표

- `GET /admin/imports` 임포트 이력 조회 API를 제공한다.
- 전체 이력을 type/status 조건으로 필터링하고 페이지네이션한다.
- `ImportBatch` 필드로 `PENDING`, `COMMITTED`, `EXPIRED` 상태를 파생한다.
- COMMITTED batch에는 실제 감사 행 기준 section별 CREATE/UPDATE/SKIP 결과를 제공한다.
- PENDING/EXPIRED batch와 nullable 업로더를 안전하게 표현한다.
- 조회 API에서 preview 원문은 외부에 노출하지 않는다.

### 🔌 API 개요

```http
GET /admin/imports?type=BUNDLE&status=COMMITTED&page=0&size=20
Authorization: Bearer {adminAccessToken}
```

| 항목 | 계약 |
| --- | --- |
| HTTP Method | `GET` |
| Endpoint | `/admin/imports` |
| 인증 | `/admin/**` 관리자 JWT 계약 적용. 인증 기능 자체 구현은 제외 |
| `type` | 선택. `BUNDLE`, `FESTIVALS`, `LINEUPS`, `ARTISTS` |
| `status` | 선택. `PENDING`, `COMMITTED`, `EXPIRED` |
| `page` | 선택. 기본값 `0`, 최소값 `0` |
| `size` | 선택. 기본값 `20`, 최소값 `1`, 최대값 `50` |

- `/api` prefix를 붙이지 않는다.
- enum은 영문 대문자 API 계약을 사용한다.
- `type`과 `status`를 모두 생략하면 전체 이력을 조회한다.
- 두 필터를 함께 전달하면 AND 조건으로 적용한다.
- 유효하지 않은 page/size는 기존 parameter/error convention에 따라 `400 Bad Request`로 처리한다.
- 기본 정렬은 `uploadedAt DESC`, 동률이면 `id DESC`다.
- 필터는 페이지네이션 전에 DB query에 적용하여 `totalElements`와 `totalPages`가 실제 필터 결과와 일치해야 한다.
- 응답 페이지 정보는 기존 `PageResponse`와 동일한 `items`, `page`, `size`, `totalElements`, `totalPages`, `hasNext`, `hasPrevious` 구조를 사용한다.

### 🧭 상태 파생

별도 `ImportBatchStatus` DB 컬럼이나 Flyway migration을 추가하지 않고 조회 시점의 `Instant now`와 `ImportBatch` 필드로 상태를 계산한다.

우선순위는 다음과 같다.

1. `committedAt != null` → `COMMITTED`
2. `committedAt == null && expiresAt <= now` → `EXPIRED`
3. 그 외 → `PENDING`

따라서 commit된 batch는 `expiresAt`이 과거여도 항상 `COMMITTED`다. `expiresAt == now`는 `EXPIRED`다.

시간 비교는 Issue #39에서 사용하는 주입 가능한 `Clock`의 `Instant`를 재사용한다. 상태 판정에는 지역 시간대 변환이 필요하지 않으며, API 시간 필드는 UTC ISO-8601 `Instant`로 직렬화한다.

응답 필드의 의미:

- `importId`: `ImportBatch.id`인 `Long`
- `type`: 업로드 유형
- `fileNames`: 업로드 당시 저장된 파일명 배열
- `status`: 조회 시점에 파생한 상태
- `uploadedBy`: `ImportBatch.uploadedByAdmin.username`인 nullable String. `uploadedByAdmin`이 null이면 null
- `uploadedAt`, `expiresAt`, `committedAt`: UTC ISO-8601 `Instant`; 미commit batch의 `committedAt`은 null
- `expiresAt`: 현재 상태와 별개로 해당 preview가 원래 언제까지 유효했는지를 나타내며 COMMITTED에서도 반환
- `result`: COMMITTED batch의 실제 반영 결과. PENDING/EXPIRED에서는 null
- preview 원문과 원본 CSV payload는 목록 응답에 포함하지 않는다.

### 📊 History result 집계

COMMITTED batch의 result는 `ImportBatch.preview`가 아니라 `ImportCommitRow`에서 집계한다.

근거:

- preview action은 예상 결과이며 실제 실행 결과와 다를 수 있다.
- Issue #39는 preview 이후 Festival 발행 시 UPDATE를 실제 SKIP으로 전환하여 감사 action에 기록한다.
- partial commit에서 선택하지 않은 row는 `ImportCommitRow`가 생성되지 않는다.
- 단일 transaction 실패는 전체 rollback되므로 COMMITTED batch의 audit row는 실제 성공 처리된 행만 나타낸다.

집계 기준:

- batch별 `section`과 실제 `action`을 기준으로 count한다.
- section은 `ARTISTS`, `FESTIVALS`, `LINEUPS`를 각각 응답의 `artists`, `festivals`, `lineups`로 매핑한다.
- action은 `CREATE`, `UPDATE`, `SKIP`을 각각 `created`, `updated`, `skipped`로 매핑한다.
- history API에서는 `failed`를 반환하지 않는다.
- 해당 조합의 감사 행이 없으면 `0`으로 반환한다.
- partial commit result에는 실제 선택되어 처리되고 감사 행이 생성된 row만 포함한다.
- Lineup은 전체 교체 계약상 `updated = 0`이어야 한다.
- commit response를 `ImportBatch`에 별도 중복 저장하거나 preview 예상값으로 result를 재구성하지 않는다.

페이지의 batch ID 목록을 기준으로 `ImportCommitRow`를 한 번에 그룹 집계하여 batch별 추가 조회가 발생하지 않도록 한다.

### 👤 uploadedBy 처리

- `ImportBatch.uploadedByAdmin`은 nullable이다.
- 현재 `AdminUser`에는 별도 표시명 필드가 없고 `username`만 존재한다.
- 백엔드는 null을 `알 수 없음` 같은 표시 문구로 변환하지 않는다.
- 표시 문구는 프론트엔드가 처리한다.
- 관리자 삭제 후에도 ImportBatch 이력은 유지되어야 한다.

### ⏳ preview 및 만료 lifecycle

- preview 유효시간은 업로드 시점부터 30분이다.
- 만료된 batch 행 자체는 이력으로 유지한다.
- Issue #39 계약대로 commit 성공 후에도 preview는 유지한다.
- history API는 preview 원문을 응답에 노출하지 않는다.
- DEC-0055에 따라 만료된 preview는 batch 이력을 유지한 채 정리할 수 있다.
- preview가 이미 정리된 EXPIRED batch도 `committedAt`과 `expiresAt`만으로 상태 조회가 가능하다.
- 이번 이슈에서는 preview cleanup을 구현하지 않는다.
- GET 조회 시 lazy cleanup을 하지 않고 scheduler도 추가하지 않는다.
- EXPIRED batch와 preview는 현재 상태 그대로 유지하며 cleanup 정책과 실행 주체는 별도 후속 이슈로 분리한다.

### 🗄️ Repository / 조회 설계

- `ImportBatchRepository`에 type/status 조건과 pageable을 함께 처리하는 조회를 추가한다.
- 파생 status 조건은 DB query에 반영하여 필터 후 페이지네이션과 count query가 정확해야 한다.
- 페이지의 COMMITTED batch ID를 대상으로 `ImportCommitRowRepository`에서 section/action별 grouped count를 bulk 조회한다.
- nullable `uploadedByAdmin`은 페이지 조회에서 안전하게 읽되 batch별 lazy loading으로 N+1이 발생하지 않도록 fetch join, entity graph 또는 projection 중 현재 repository convention에 맞는 방식을 사용한다.
- preview 본문을 history DTO로 역직렬화하지 않는다.
- 별도 status 컬럼, history 테이블, migration을 추가하지 않는다.

#### 실제 commit 결과

- `ImportCommitRow`는 batch, section, line, importKey, 실제 action, nullable FK, 원본 payload, committedAt을 저장한다. — DEC-0077, Issue #39
- 감사 action은 `CREATE`, `UPDATE`, `SKIP`이며 SKIP도 기록한다. — DEC-0077

- 이력 result는 예상 preview가 아니라 실제 audit 결과를 기준으로 해야 partial commit과 실제 action을 정확히 반영할 수 있다.
- 시간 응답은 Issue #39 commit response와 동일하게 UTC ISO-8601 `Instant`로 통일한다.

#### History API 최종 계약

- 상태는 주입된 `Clock`의 `Instant now`를 기준으로 다음 순서로 파생한다.
  1. `committedAt != null` → `COMMITTED`
  2. `committedAt == null && expiresAt <= now` → `EXPIRED`
  3. 그 외 → `PENDING`
- `expiresAt == now`는 EXPIRED이며, expiresAt이 과거라도 committedAt이 있으면 COMMITTED다.
- 기본 정렬은 `uploadedAt DESC`, 동률이면 `id DESC`다.
- page 기본값은 0이다.
- size 기본값은 20이고 허용 범위는 1~50이다.
- 잘못된 page/size는 `400 Bad Request`로 처리한다.
- status filter는 파생 조건을 DB query에 반영하고 pagination/count 이전에 적용한다.
- type과 status를 함께 전달하면 AND 조건으로 처리한다.
- COMMITTED result는 `ImportCommitRow`를 batch/section/action으로 bulk grouped 집계한다.
- result에는 section별 `created`, `updated`, `skipped`만 반환하며 `failed`는 포함하지 않는다.
- 존재하지 않는 action count는 0이다.
- PENDING/EXPIRED의 result는 null이다.
- partial commit은 실제 감사 행이 존재하는 선택 row만 집계한다.
- Festival preview UPDATE가 실제 SKIP으로 실행된 경우 `skipped`에 집계한다.
- `uploadedBy`는 nullable String이며 `uploadedByAdmin.username`을 반환한다. 관계가 null이면 응답도 null이다.
- `uploadedAt`, `expiresAt`, `committedAt`을 모두 UTC ISO-8601 Instant로 반환한다.
- COMMITTED에서도 원래 preview 유효기한 이력인 `expiresAt`을 그대로 반환한다.
- 한 페이지의 COMMITTED batch ID를 모아 한 번의 grouped query로 결과를 집계하며 batch별 query를 실행하지 않는다.
- 이번 API는 read-only다. history 조회 시 ImportBatch.preview를 변경하거나 삭제하지 않고 lazy cleanup 및 scheduler를 추가하지 않는다.
