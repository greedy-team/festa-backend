## 제목

🚀 [기능요청][관리자][대시보드] 축제 데이터 구축·검수 현황 API 추가

## 본문

## 📝 배경

- 관리자 대시보드의 첫 목적은 발행·미발행 축제 현황, 특히 아직 발행하지 못한 대상을 드러내는 것이다. 무엇이 비어 있는지 보여야 운영자가 축제 존재 여부를 확인하고 크롤러의 수동 입력 또는 축제 검수 흐름으로 이어갈 수 있다.
- 현재 백엔드에는 Host·Festival·Lineup과 임포트 감사 Entity가 있으나, 전체 대학을 기준으로 데이터 구축·검수 진행 상황을 집계하는 API는 없다.
- 현재 존재하는 Host 목록 조회는 Host별 전체 Festival 수만 제공하며, 발행 완료·검수 대기·확인 필요 상태와 등록 진행률을 구분하지 않는다.

## 🎯 목표

- 전체 Host를 기준으로 대학별 축제 데이터의 구축 및 검수 진행 상황을 한눈에 확인할 수 있는 API를 제공한다.
- 다음 요약 정보를 제공한다.
  - 전체 주최 수
  - 발행 완료 Host 수
  - 검수 대기 Host 수
  - 확인 필요 Host 수
  - 등록 진행률
- 기본 목록에는 `REVIEW_PENDING`, `NEEDS_CHECK` 상태의 Host만 페이지로 제공한다.
- 각 목록 항목은 주최명, 대표 축제명, 대표 축제 기간, 상태, Host Instagram 링크를 제공한다.
- 검수 대기 항목은 축제 검수 화면으로 이동할 수 있도록 `festivalId`를 제공한다.
- 확인 필요 항목은 직접 등록 흐름으로 이동할 수 있도록 `hostId`를 제공한다.

## 🌐 API 개요

- Method: `GET`
- Endpoint: `/admin/festivals/coverage`
- 인증: 관리자 JWT 인증 필요. 별도 관리자 역할 등급은 두지 않는다.
- Query Parameter
  - `year`: `Festival.startDate`의 연도. 생략하면 현재 연도
  - `status`: `PUBLISHED`, `REVIEW_PENDING`, `NEEDS_CHECK`. 생략하면 `REVIEW_PENDING`, `NEEDS_CHECK` 조회
  - `page`: 0부터 시작하는 페이지 번호
  - `size`: 페이지 크기. 기본 20, 허용 범위 1~50
- 응답 최상위는 `year`, `summary`, `hosts`를 반환하고 `hosts`는 공통 `PageResponse` 구조를 사용한다.
- `summary`
  - `totalHosts`: 전체 Host 수
  - `published`: `PUBLISHED` Host 수
  - `reviewPending`: `REVIEW_PENDING` Host 수
  - `needsCheck`: `NEEDS_CHECK` Host 수
  - `coverageRate`: 등록 진행률
- `hosts`의 공통 페이지 정보
  - `items`
  - `page`
  - `size`
  - `totalElements`
  - `totalPages`
  - `hasNext`
  - `hasPrevious`

```json
{
  "year": 2026,
  "summary": {
    "totalHosts": 29,
    "published": 18,
    "reviewPending": 4,
    "needsCheck": 7,
    "coverageRate": 62
  },
  "hosts": {
    "items": [],
    "page": 0,
    "size": 20,
    "totalElements": 11,
    "totalPages": 1,
    "hasNext": false,
    "hasPrevious": false
  }
}
```
- 각 item에 포함할 정보
  - `hostId`
  - `festivalId`
  - 주최명
  - 축제명
  - 시작일
  - 종료일
  - 상태
  - `Host.instagramUrl`
- `NEEDS_CHECK`에 현재 대상 Festival이 없으면 `festivalId`, 축제명, 시작일, 종료일은 null을 허용한다.

## 📊 Host 상태 판정

- 집계와 목록의 단위는 Festival이 아니라 Host다.
- `year` 조건은 `Festival.startDate`의 연도로 판정한다.
- “오늘”은 `Asia/Seoul` 기준 날짜다.
- 진행 중 또는 예정 Festival은 `endDate >= 오늘`로 판정한다.
- 한 Host에 Festival이 여러 개면 다음 우선순위로 대표 상태를 계산한다.
  1. 조회 연도의 미발행 Festival이 하나라도 있으면 종료 여부와 관계없이 `REVIEW_PENDING`
  2. 미발행 Festival이 없고 `endDate >= 오늘`인 발행 Festival도 없으면 `NEEDS_CHECK`
  3. 그 외 발행 완료 상태는 `PUBLISHED`
- 의도한 상태 예시
  - 과거에 종료됐더라도 미발행 Festival이 있으면 `REVIEW_PENDING`
  - 미래 또는 진행 대상 미발행 Festival이 있으면 `REVIEW_PENDING`
  - 발행된 미래 또는 진행 대상 Festival이 있고 미발행 대상이 없으면 `PUBLISHED`
  - 과거에 발행된 Festival만 있고 오늘 이후 Festival이 없으면 다음 축제 확인을 위해 `NEEDS_CHECK`
- 현재 Entity에는 `Host`, `Festival.startDate`, `Festival.endDate`, `Festival.publishedAt`이 있어 이 상태 계산에 필요한 데이터가 존재한다.
- 한 Host에 같은 우선순위의 Festival이 여러 개면 대표 Festival은 검수 대상 중 `startDate ASC`, 동일하면 `id ASC`로 선택한다.

## 📈 집계 기준

- 전체 주최 수는 조회 연도와 관계없는 전체 Host 수다.
- 상태별 수는 위 판정에 따른 Host 수다.
- 등록 진행률은 `PUBLISHED / totalHosts * 100`으로 계산한다.
- 등록 진행률은 정수 단위로 반올림한다.
- `totalHosts`가 0이면 `coverageRate`는 0이다.
- `status` 필터는 paged items에 적용하고, summary는 전체 세 상태의 현황을 제공한다.
- 기본 목록은 `REVIEW_PENDING → NEEDS_CHECK` 순서로 정렬하고, 같은 상태 안에서는 `hostName ASC`로 정렬한다.

## ✅ 완료 조건

- `GET /admin/festivals/coverage`가 Host 단위 summary와 paged items를 하나의 응답으로 반환한다.
- 응답 최상위에 `year`, `summary`, `hosts`가 포함되고 `hosts`에 `items`, `page`, `size`, `totalElements`, `totalPages`, `hasNext`, `hasPrevious`가 포함된다.
- `year`를 생략하면 현재 연도, 지정하면 `Festival.startDate`가 해당 연도인 Festival을 기준으로 상태를 판정한다.
- “오늘”은 `Asia/Seoul` 기준이며 진행 중·예정 Festival은 `endDate >= 오늘`로 판정한다.
- 조회 연도에 과거 종료된 미발행 Festival만 있어도 해당 Host는 `REVIEW_PENDING`이다.
- 전체 Host 수와 `PUBLISHED`, `REVIEW_PENDING`, `NEEDS_CHECK` Host 수가 동일한 상태 판정 기준으로 계산된다.
- `summary`에 `totalHosts`, `published`, `reviewPending`, `needsCheck`, `coverageRate`가 포함된다.
- `coverageRate`가 `PUBLISHED / totalHosts * 100`으로 계산되고 정수로 반올림된다.
- `totalHosts`가 0이면 `coverageRate`는 0이다.
- 상태 필터를 생략하면 `REVIEW_PENDING`, `NEEDS_CHECK` 목록만 반환하고 `PUBLISHED`는 제외한다.
- `status=PUBLISHED`, `status=REVIEW_PENDING` 또는 `status=NEEDS_CHECK`를 지정하면 해당 상태만 반환한다.
- status 필터는 items에만 적용하고 summary는 항상 전체 Host의 세 상태 현황을 유지한다.
- 기본 목록은 `REVIEW_PENDING → NEEDS_CHECK`, 같은 상태에서는 `hostName ASC`로 정렬된다.
- 같은 Host에 동일 우선순위 Festival이 여러 개면 `startDate ASC`, 동일하면 `id ASC`인 Festival을 대표로 선택한다.
- 검수 대기 항목에 대표 `festivalId`, 확인 필요 항목에 `hostId`가 포함된다.
- 목록에 주최명, 대표 축제명, 기간, 상태, `Host.instagramUrl`이 포함된다.
- 대상 Festival이 없는 `NEEDS_CHECK` 항목은 `festivalId`, 축제명, 시작일, 종료일이 null일 수 있다.
- 기존 공통 페이지 응답 필드가 유지된다.
- 관리자 인증이 없는 요청은 인증 계층의 공통 401 응답을 따른다.
- 관련 테스트가 모두 통과한다.

## 🧪 테스트 항목

- `coverageRate` 계산과 정수 반올림
- `totalHosts=0`일 때 `coverageRate=0` 처리
- status 생략 시 `REVIEW_PENDING`, `NEEDS_CHECK`만 조회되고 `PUBLISHED`가 제외되는 경우
- `status=PUBLISHED`, `status=REVIEW_PENDING`, `status=NEEDS_CHECK` 필터
- status 필터를 적용해도 summary가 전체 Host 현황을 유지하는 경우
- 지원하지 않는 status 값 검증
- 기본 상태 정렬 `REVIEW_PENDING → NEEDS_CHECK`
- 같은 상태에서 `hostName ASC` 정렬
- `page`, `size` 및 빈 페이지
- `Host.instagramUrl`이 있는 경우와 null인 경우
- Festival이 없는 `NEEDS_CHECK` 항목의 Festival 관련 필드가 null인 경우
- `REVIEW_PENDING` 항목에 대표 `festivalId`가 포함되는 경우
- 인증 토큰 없음·만료 시 공통 401 처리

- 관리자 대시보드의 첫 목적은 발행·미발행 현황, 특히 미발행 축제를 드러내는 것이다. 근거: DEC-0048.
- 대시보드 집계 단위는 Host다.
- 전체 주최 수는 전체 Host 수다.
- 기본 목록은 `REVIEW_PENDING`, `NEEDS_CHECK`만 제공하고 `PUBLISHED`는 제외한다.
- status 필터는 `PUBLISHED`, `REVIEW_PENDING`, `NEEDS_CHECK`를 지원하며 생략하면 `REVIEW_PENDING`, `NEEDS_CHECK`를 조회한다.
- `year`는 `Festival.startDate`의 연도를 기준으로 하며 생략하면 현재 연도를 사용한다.

- Festival 발행 여부는 별도 boolean이 아니라 `publishedAt` 존재 여부로 판정한다.
- 조회 연도의 미발행 Festival은 과거 종료 여부와 관계없이 `REVIEW_PENDING`을 유지한다.
- 미발행 Festival이 하나라도 있으면 `REVIEW_PENDING`이 다른 상태보다 우선한다.
- 과거 발행 Festival만 있고 오늘 이후 Festival이 없으면 `NEEDS_CHECK`로 돌아간다.
- 같은 우선순위의 Festival이 여러 개면 `startDate ASC`, 동일하면 `id ASC`로 대표 Festival을 선택한다.
- 기본 목록은 `REVIEW_PENDING → NEEDS_CHECK`, 같은 상태에서는 `hostName ASC`로 정렬한다.
- 등록 진행률 필드명은 `coverageRate`다.
- `coverageRate`는 `PUBLISHED / totalHosts * 100`이며 정수 단위로 반올림한다.
- `totalHosts`가 0이면 `coverageRate`는 0이다.
- Instagram 링크는 `Host.instagramUrl`을 사용한다.
- 하나의 endpoint에서 최상위 `year`, `summary`, `hosts`를 반환하고 `hosts`는 공통 `PageResponse` 구조를 사용한다.
- status 필터는 items에만 적용하고 summary는 항상 전체 Host 상태를 유지한다.
- 대상 Festival이 없는 `NEEDS_CHECK` 항목은 Festival 관련 필드의 null을 허용한다.
- 모든 API 경로에는 `/api` 접두사를 붙이지 않는다. 근거: DEC-0084.
- 관리자 API는 자체 아이디·비밀번호 로그인으로 발급한 JWT 인증을 요구한다. 근거: DEC-0082.

- 백엔드와 관리자 대시보드에서 크롤러 또는 AI를 직접 호출하지 않는다. 크롤링·직접 입력은 별도 흐름이다. 근거: DEC-0047.
