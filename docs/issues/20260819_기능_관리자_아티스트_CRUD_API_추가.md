## 본문

## 📝 현재 문제점

- 임포트는 크롤러가 준 아티스트를 자동으로 만들되 확신하지 못한 것에 `needsReview`를 붙인다. 표시만 될 뿐 그것을 열어보고 고칠 API가 없다
- 장르와 이미지, 인스타그램 주소는 크롤링으로 얻기 어려워 사람이 채워야 하는데, 넣을 방법이 데이터베이스에 직접 넣는 것뿐이다
- 크롤러가 못 잡은 아티스트를 직접 등록할 수단이 없다
- 별칭은 임포트가 라인업의 이름을 아티스트에 맞출 때 쓰는 키다. 별칭이 없으면 같은 아티스트가 표기만 다른 채로 여러 개 생기는데, 지금은 별칭을 넣을 경로가 없다

## 🛠️ 해결 방안 / 제안 기능

- 관리자용 아티스트 등록·목록·수정·삭제 API를 만든다
  - 목록 — GET /admin/artists
  - 등록 — POST /admin/artists
  - 수정 — PATCH /admin/artists/{id}
  - 삭제 — DELETE /admin/artists/{id}
- 경로에 /api 접두사를 붙이지 않는다. 주최 API는 접두사가 붙은 채로 머지되어 지금 걷어내는 중이므로(#26) 아티스트는 처음부터 붙이지 않는다
- 목록은 병합 검토 대기 필터·검색어·장르 필터·정렬을 받는다. 정렬은 등록 역순이 기본이고 출연 횟수순과 이름순을 지원한다. 검색어는 이름과 별칭을 함께 본다. 페이지 크기는 기본 20이고 1~50을 벗어나면 오류다
- 수정은 보내온 항목만 반영한다. 항목을 보내지 않으면 기존 값을 그대로 두고, 빈 값으로 보내면 비운다
- 별칭은 통째로 교체한다. 수정 요청에 별칭 배열이 오면 그 배열이 최종 상태가 된다. 배열을 보내지 않으면 기존 별칭을 건드리지 않는다
- 이름은 중복을 허용하지 않는다. 별칭도 전체에서 유일하다. **아티스트 이름과 다른 아티스트의 별칭이 겹치는 것은 데이터베이스가 막지 못하므로 서비스에서 양쪽을 함께 확인한다** — 겹치면 임포트가 이름으로 찾을 때 두 건이 나와 어느 쪽인지 판단할 수 없게 된다
- 출연 이력이 있는 아티스트는 삭제하지 않는다. 라인업이 아티스트를 참조하고 있어 데이터베이스가 삭제를 거부하는데, 걸러내지 않으면 잘못된 요청이 서버 오류로 나간다. 전용 에러 코드로 응답한다
- 삭제할 때 별칭 행을 먼저 지운다. 별칭도 아티스트를 참조하므로 남겨두면 삭제가 실패한다
- 인스타그램 주소를 등록·수정 요청에 넣는다. **API 명세는 이 항목을 응답에만 두어 값을 넣을 경로가 없다** — 컬럼도 있고 응답에도 나가는데 채울 방법이 없는 상태다
- **아티스트 이미지 주소는 요청에서 받지 않는다.** 응답 항목은 그대로 두되 값은 항상 비어 있다. 아티스트 사진을 쓰지 않고 기본 이미지로 대체하기로 한 결정이 그대로 유효하다 — 파일을 우리가 저장하지 않고 주소만 두더라도 초상권은 "얼굴을 영리 서비스에 띄웠는가"로 판단하므로 주소만 두는 방식으로는 해결되지 않는다. 명세는 이 항목을 입력받도록 적고 있으나 따르지 않는다
- 출연 횟수는 저장하지 않고 조회할 때 라인업을 세어 계산한다
- 에러는 앞서 정한 공통 규약을 그대로 쓴다. 아티스트 전용 에러 코드는 이 작업에서 도메인 코드 목록으로 추가한다
- **에러 코드 이름은 도메인을 앞에 두는 규칙을 따른다.** 명세의 `DUPLICATE_ARTIST_NAME`·`ARTISTS_INVALID_GENRE_TYPE`은 표기 오류이며 `ARTIST_DUPLICATE_NAME`·`ARTIST_INVALID_GENRE_TYPE`이 맞다
- 별칭 중복에 쓸 에러 코드는 어디에도 없다. 이 작업에서 새로 만든다
- 권한 없음(403) 응답은 만들지 않는다. 관리자 권한을 나누지 않기로 했으므로 관리자 API는 인증만 요구하고 권한 부족은 발생하지 않는다

## ⚙️ 작업 내용

- 아티스트 저장소·서비스·컨트롤러 추가
- 등록·수정 요청 형식, 목록·단건 응답 형식 정의
- 목록 필터·검색·정렬·페이지 처리. 페이지 응답은 주최에서 만든 공통 형식을 그대로 쓴다
- 출연 횟수 집계 조회 — 주최 목록이 축제 수를 세는 것과 같은 방식
- 별칭 동기화(교체·중복 확인)와 삭제 시 별칭 정리
- 아티스트 도메인 에러 코드 정의
- 요청 값 검증 연결 — 이름·별칭 길이, 검색어 길이, 페이지 범위, 정렬·장르 값, 이름 중복, 별칭 중복, 이름과 별칭의 교차 중복, 없는 아티스트 수정·삭제, 출연 이력이 남은 아티스트 삭제
